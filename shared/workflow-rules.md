# 工作流唯一规则

本文件只定义跨岗位流程。岗位 `SKILL.md` 只写本岗位怎么做；账号 `config.md` 保存定位与有明确范围、退出条件的账号阶段实验；`account-rules.md` 只写已确认偏好或稳定规则。

## 状态真相

- `studio-state.json`：当前账号、当前视频。
- 当前项目 `brief.md`：阶段、阶段状态、阻塞原因、工作模式、风险等级、平台计划。
- 实际产物：判断环节是否完成。空模板、占位值、仅有文件名都不算完成。
- 阶段和产物冲突时，不静默猜测或推进；先报告冲突，再修正。
- 每个 Codex 任务首次定位项目后锁定该项目路径；`studio-state.json.current_video` 后续变化不自动改变本任务。只有老板明确说“切换到/改做另一个项目”才重新绑定，并先复述新路径。
- `brief.md` 生命周期字段只通过 `.codex/skills/studio-manager/scripts/set_project_state.py` 修改。工具负责枚举校验、工作流校验、失败回滚和看板刷新；岗位不得手改这三个字段。

阶段状态只用：

- `进行中`
- `等待老板确认`
- `阻塞`
- `完成`

`阻塞原因` 无阻塞时写“无”；等待确认时写清确认对象。

## 工作模式与确认点

标准和快速模式都只暴露四张批准卡；工作模式只控制过程产物颗粒度，不改变老板确认次数，也不控制证据强度。

### 标准模式

固定四张决策卡：

1. **选题卡**：目标观众、具体问题、核心承诺、证据与缺口、主要实验变量。
2. **内容与开拍卡**：大纲、逐字稿、标题/发布文案、分镜、拍摄清单、素材缺口、录屏/收音/平台规格、封面方向与生成输入合并呈现；多资产项目同时呈现主资产接触表。
3. **制作预览卡**：先交 10 秒无精修留存样片（同时作为技术预检，覆盖解码、抠像、字幕、录屏清晰度和导出链路）和代表关键帧；确认即授权按同一方向完成全片和动效，不再逐项询问。配乐和音效不在此卡单独确认，剪完整片后按账号声音系统一次性铺上；合成旁白按下方“旁白与后期声音”规则先定。
4. **完整成片与发布卡**：完整第一版、统一音乐/音效/动效、平台 UI 遮挡预览、标题/正文/封面和独立审核结论合并确认。

岗位间其余交接自动进行。老板对一张决策卡回复“可以”，只表示批准该卡列出的范围；系统随后自动推进到下一张有实质判断的决策卡，不再询问“是否继续”。

四张决策卡呈现时，负责岗位必须附至少一条基于专业标准（算法认知、受众心理或视觉美学）的主动判断或风险提示，说明这么做的理由，不能只交产物不表态。岗位间其余自动交接不强制附加，避免逐环节啰嗦。

选题卡同时确定本期生产策略：

- **探索性实验**：新形式、新钩子或低成本表达测试；优先快速模式，做到足以验证主要变量的完整质量，不为未验证方向提前堆满包装。
- **已验证模式复用**：已有跨视频证据支持的结构或表现形式；保持已验证的 Lego 砖，只改变一个主要变量。

大纲先产出一版临时包装原型，只包含临时标题、封面核心画面、首帧/第一句话和首个可见兑现及预计时间；它是过程产出，不新增批准点。正式分平台发布包由编剧在内容与开拍卡前完成。临时标题/首句钩子须先给 2-3 个候选并附各自优劣分析，同时询问老板本人是否有既定方向，综合两者定稿，不由提案师单方案直接写死。每期同时写清体验峰值和结束记忆，不为此新增文件或确认点。

### 快速模式

同样固定四张决策卡，但允许过程文件简版：

1. 选题卡。
2. 内容与开拍卡。
3. 制作预览卡。
4. 完整成片与发布卡。

交接文件仍需存在，但允许简版；同一信息不在多个文件重复填写。

快速模式默认用于风险 C、低成本且只验证一个主要变量的内容；标准模式默认用于风险 A/B、4 分钟以上教程、新工具链、高制作成本或多平台复杂交付。工作模式只改变过程产物颗粒度，不降低真实性、技术预检、独立审核或发布记录要求。

“完整成片与发布”确认点只表示老板确认最终版本可以发布，不表示系统已经代发或作品已经上线。只有老板报告实际发布结果后，才能创建 `07publish/publish.md` 并登记“已发布”。

### 过程产出与阶段产出

- 每个岗位都必须留下真实、可打开、可交接的过程产出；过程产出进入老板看板，可随时查看，默认自动交给下一岗位，不等待批准。
- 只有四张决策卡对应的阶段产出需要老板批准。不得把岗位交接、技术检查、素材批次、动效选择、音乐选择或模型选择升级为新确认点。
- 老板主动查看过程产出并提出修改时，按反馈处理；未提出修改不视为默许错误，岗位仍须完成自检和独立审核。

### 允许额外打断的异常

四张决策卡之外，只允许以下情况暂停并询问老板：

1. 缺少无法替代的真人素材、原始文件或账号权限。
2. 健康、带货、版权等高风险事实无法验证。
3. 需要付费、消耗明显额度或连接新的外部服务。
4. 发布、删除、覆盖正式成片等不可逆操作。
5. 默认工具失败，备用方案会明显改变内容或画面效果。

普通素材选择、动效、音乐、音效、模型小样、技术修复和岗位交接由团队自行判断。

## 生命周期硬门槛

- 已有想法也必须留下 `brief.md` 和大纲；快速模式可用简版。
- 没有逐字稿和分镜，不进入正式拍摄或剪辑。
- 大纲必须写明首个可见兑现及预计时间。教程或演示内容优先在前 10—15 秒给出真实结果、前后状态或操作证据；确实不能做到时写清物理或叙事原因，不用空口承诺代替兑现。
- 正式精修前先做 10 秒无精修留存样片，同时承担首次解码、抠像、字幕、录屏或导出链路的技术预检，不再单独出 30 秒样片。配乐和音效不在预览阶段单独确认，剪完整片后按账号声音系统一次性铺上；合成旁白先完成验收并用于预览时序。
- 每个内容段至少带来一种新变化：新事实、新情绪、新结果或新视觉证据；四项都没有的段落删除或合并。
- 没有真实成片和发布前独立审核“通过”，不得登记发布。
- `edit-log.md`、发布前审核、预测和发布记录必须引用同一个锁定成片相对路径与 SHA-256；任一处不一致视为版本已变更，必须重新审核或重新预测。
- 发布前预测必须在审核通过后、看到任何发布数据前完成；已经看到数据时不得倒填盲预测。
- 默认按平台记录 T+1、T+7。分发仍在明显变化、出现异常或需要判断短期扩散时补 T+3；常青搜索、带货长尾或假设尚未收敛时补 T+30。保留每次采集时间，不用后一次数据覆盖前一次数据。
- 发布状态、发布时间、链接、包装版本和数据快照按平台独立校验，不得跨平台拼接字段形成“已发布”或“已复盘”。
- 当前账号和视频不得跨账号猜测、混用产物或套用未验证规律。
- 外部工具不可用时必须记录降级和缺口，不得声称已经搜索、生成、剪辑、导出或发布。

## 旁白与后期声音

项目要求合成旁白时，资产制片根据编剧定稿准备朗读稿、生成音轨并完成逐句验收；剪辑师接收已选定音轨，安排字幕、人物口型、操作画面和混音。首次音色选择合并进现有内容与开拍卡或制作预览卡，不新增批准卡。人物和详细时间线锁定前先定旁白；配乐与音效仍在全片后铺。修改旁白须登记版本与受影响稿段/镜头，再检查下游同步。原稿事实或承诺改变交回编剧，合成音频错误交资产制片，混音和时间线错误交剪辑师。

## 风险等级与证据

风险等级控制调研、事实核验和审核强度，与工作模式独立。

- `A`：健康功效、带货承诺、医疗/保健资质、高成本制作、重大时效事实。完整验证；高风险说法必须有当前权威来源。
- `B`：普通教程、经验分享、常规产品体验。验证核心需求、官方事实和至少两个有效样本；不为“爆款”结论凑样本。
- `C`：低成本趋势试验、表达测试、轻量内容。可带证据缺口发布，但必须标记为实验，不把弱证据写成确定结论。

若要声称“平台异常机会”或“跨账号稳定机会”，仍执行账号提案规则中的完整异常样本门槛。

风险等级只在选题卡定级一次，不代表中途不能改。任一岗位在制作过程中发现实际风险高于选题卡定级（例如中途加入带货、涉及健康表述），必须暂停并请提案师重新定级，不得按原定级继续制作；提案师复核后用 `set_project_state.py` 更新 `brief.md` 的风险等级，其余流程不受影响。

### A 级前置审查

风险 A 的内容在“内容与开拍卡”老板确认通过后，必须由审核员追加一次轻量前置审查：只核对核心承诺和事实基础是否成立（对照 `outline.md`、`script.md` 和 `01assets/research.md`），不查成片、不查动效。审查在当前上下文执行，不必启动独立子 Agent。有阻断项时按“退回与复核”处理，退回提案师或编剧；无阻断项直接放行，不重复占用发布前独立审核的额度。风险 B、C 不强制此步骤。

## 产物按阶段创建

新项目只创建八个阶段目录和 `brief.md`。以下文件到使用阶段再从模板创建：

- 审核通过后、发布前：`prediction.md`
- 发布前审核开始：`06video/review.md`
- 完整成片与发布卡生成时：`07publish/upload-kit.md`（发布上传总清单，只读汇总）
- 登记发布：`07publish/publish.md`
- 首次复盘：`08retro/retro.md`

文件已存在但仍为空模板时，按“未完成”处理。

### 文件分层与单一来源

- `06video/` 顶层只放正式交付物和生命周期记录；过程工程、缓存与中间渲染按需放 `06video/_work/`，候选图、样片与审核预览按需放 `06video/_preview/`。两目录仅在首次需要时创建。
- `02script/script.md` 是口播正文唯一来源；需要提词时再由它生成 `念稿.md`，不双向维护。
- 屏幕文字以导演/剪辑视觉方案为来源；需要交接清单时再生成 `on-screen-copy.md`，不得形成第二套文案事实。
- 平台封面和正文从内容母版派生；完整成片与发布卡必须同时展示平台 UI 遮挡后的标题、正文、字幕和画面安全区。
- `07publish/upload-kit.md` 是 `publish-pack.md`、`asset-manifest.md`、`edit-log.md` 的只读汇总，供老板实际上传时一次查齐封面路径、标题、正文、TAG 和分段；不是第二套文案或路径事实，三份来源改动后必须重新生成，不在此文件单独修改。

### 知识分层

- 外部或个人 WIKI 保存完整理论、来源、案例和争议；工作台不复制整篇知识。
- `shared/skill-bases/` 只保留跨账号执行检查、红旗、验收标准和必要的 WIKI 指针，不把来源观点写成平台事实或心理学定律。
- 账号 `skill-base/<岗位>/account-rules.md` 只保存老板明确锁定的偏好，或至少三条独立视频支持且无明显反例的稳定规则。
- 当前项目 `01assets/` 只保存本期实际采用的结论、必要摘录和来源；版本、价格、功能、平台规则等时效事实仍须查当前官方来源。

### 目标观众冷看

账号 `config.md` 的阶段实验规定了早期冷读时，在“内容与开拍卡”提交前由审核员执行，不新增卡片、文件或生命周期阶段。审核员只看标题、封面方向、第一句话、前 15 秒和首个兑现，回答四问：这是什么主题、能拿到什么结果、为什么相信、最想在哪一刻离开。重复出现的理解或信任问题先做最小修正，再提交原卡；通过时在原卡汇总中写明“早期冷读通过”，不提前生成发布前 `review.md`。

制作预览阶段出现以下任一条件时，把 1—3 名真实目标观众冷看并入制作预览卡：账号 `config.md` 的当前阶段实验要求、首次使用的新内容形式、4 分钟以上教程、高制作成本，或上一条同类视频发生明显早段流失。冷看不新增决策卡和永久文件，只记录四项：前 5 秒理解到的主题、预期结果、开始想离开的时间点、看完后能独立完成的动作。结果摘要随本次制作预览决定写入项目 `decisions.md` 同一条记录，不另建报告。

拿不到目标观众时，在制作预览卡如实写明缺口；老板可在同一张卡内决定接受缺口或补测，不另开确认流程。连续 2—3 人指出同一理解问题时先修预览，再铺满全片。

## 平台按计划生成

只为 `brief.md` 的平台计划生成发布包、封面、预测、审核和发布记录。账号默认平台可被单项目覆盖；未计划的平台不生成空栏目。

发布包先定义内容母版，再为各平台定义包装版本。平台版本可改变标题、封面、开头节奏、发布文案和 CTA，不可静默改变核心承诺、事实和风险边界。

## 发布前独立审核

发布前审核必须使用独立子 Agent；阶段性大纲、逐字稿或分镜审查可在当前上下文执行。独立审核只接收最终产物、当前项目 `brief.md`、账号 `config.md`、账号审核规则和共享审核规则，不接收创作过程对话。主对话只接收审核报告。

审核结论只有“通过”时才能进入发布前预测和发布确认；存在阻断项时必须按“退回与复核”处理。无法启动独立子 Agent 时记录阻塞，不得以当前上下文自审代替发布前审核。

## 阶段推进

岗位完成产物后可直接调用状态工具，不必额外叫管家。一次必须同时传入：

- `当前阶段`
- `阶段状态`
- `阻塞原因`

命令：`python3 .codex/skills/studio-manager/scripts/set_project_state.py <项目路径> --stage <阶段> --status <状态> --blocker <原因> [--risk A|B|C]`。工具失败时保持原状态；不得绕过工具手改。

每次岗位交接必须在回复中明确三项：下一岗位、交接输入文件、仍存在的缺口。普通岗位交接不增加老板确认点；发布前独立审核仍按本文件强制启动独立子 Agent。

## 在制品限制

- 每个账号最多同时有 1 个制作项目（`讲戏中` 至 `审核通过`）和 1 个提案/写稿项目（`提案中`、`写稿中`）。
- 已存在的超额项目不自动删除或改状态；新建或恢复项目前，老板先明确保留哪个项目继续，其余设为“阻塞”并写清暂停原因。
- `已发布`、`已复盘` 不占在制品名额。单次返工仍算原项目，不新建平行项目。

## 退回与复核

审核阻断项必须写明：责任岗位、退回阶段、受影响文件、最小整改、复核入口。默认映射：

- 核心承诺或事实基础不成立：提案师，退回“提案中”。
- 逐字稿、标题、发布文案问题：编剧，退回“写稿中”。
- 镜头证明或拍法问题：导演，退回“讲戏中”。
- 素材、主资产身份、版权、资质或封面执行问题：资产制片，退回“素材中”。
- 合成旁白漏字、读音或生成质量问题：资产制片，退回“素材中”；定稿事实或承诺错误仍交编剧。
- 成片节奏、字幕、混音、时间线同步或导出问题：剪辑师，退回“剪辑中”。

同一问题跨岗位时只指定主责任岗位；其他岗位写入“受影响文件”。整改后由原审核员按复核入口只复核阻断项及其连带影响。

## 规则分层

1. 本文件：跨岗位硬门槛、状态、确认点。
2. `.codex/skills/<岗位>/SKILL.md`：岗位操作步骤、输入输出、自检。
3. `accounts/<账号>/config.md`：账号定位、受众、平台、创作纪律。
4. `accounts/<账号>/skill-base/<岗位>/account-rules.md`：老板明确长期偏好、三条以上独立视频支持且无明显反例的稳定规则。
5. `accounts/<账号>/learning-log.md`：观察、临时规律、被推翻假设；不得冒充正式规则。
6. `shared/skill-bases/`：跨账号专业方法。一个领域保留一个主文件；旧规则被替代时删除旧表述，不并排保留两个版本。

冲突优先级：本文件硬门槛 > 老板本次明确要求 > 账号 `config.md` > 账号稳定规则 > 共享方法 > 本期实验假设。老板本次要求可以覆盖创作偏好、工作方式和项目选择，但不能临时绕过真实性、发布前独立审核、预测时间顺序、账号隔离等硬门槛。老板要改变硬门槛时，必须先明确修改本文件；规则更新前不得按例外执行。遇到同级冲突时停止并请老板决定。

### 双速学习

- **立即采用**：老板明确偏好、错误修复、官方规格变化、已完成最小实测的低风险工具能力，以及不改变创作方向的效率优化。
- **单片实验**：新动效、新剪辑手法、新生成模型先做局部样片；一次只改变一个主要变量，通过本期验证后可在本期使用，先记入 `learning-log.md`。
- **跨片升级**：钩子、封面、节奏、平台表现等效果规律，两条独立视频支持时记为临时规律，三条以上支持且无明显反例时才升级为稳定规则。
- 新规则替代旧规则时，活跃文件只保留一个有效定义；旧表述从活跃文件删除，历史由 Git、项目 `decisions.md` 或复盘记录追溯，不保留“已废止”行。

### 稳定规则格式

效果类结论单条视频只产生观察；两条独立视频支持同一判断时可记为临时规律；三条以上独立视频支持且无明显反例时，才能升级为稳定规则。老板明确确认的长期偏好，以及已完成最小实测的低风险工具能力，可按“双速学习”直接采用；不得把未验证效果或一次偶然表现写入 `account-rules.md`。

每期只主动改变一个主要实验变量；其余变化记为混杂变量。优先从 `learning-log.md` 选择一个待验证假设；没有合适假设时明确写“探索性实验”，不得事后挑一个变量冒充预设实验。

账号 `account-rules.md` 只保留两个区块：`老板锁定偏好` 与 `数据验证规则`。老板明确的长期偏好立即进入前者；至少三条独立视频支持且无明显反例的效果规律进入后者。每条稳定规则必须包含：

- `ID`：`<账号缩写>-<岗位缩写>-<三位序号>`，一经使用不改号。
- `规则`：一条可执行判断，不混入背景故事。
- `来源`：老板确认，或至少三条支持视频路径。
- `复核条件`：何时需要重新判断。规则失效时从活跃文件删除；已用 ID 不得分配给另一条不同规则。

历史规则来源不完整时不得留在活跃规则表冒充稳定规则；需要继续观察的内容移入 `learning-log.md`，否则只由 Git 历史保留，不得伪造来源。

提案师从对标作品提炼、尚未在本账号验证的手法只能作为假设写入 `learning-log.md`；每条视频都记录观察，每完成 3 条视频批量检查升级、合并与删除。老板明确长期偏好不等待批次，立即写入 `老板锁定偏好`。

### 账号增长链与单片目标

- 知识类账号：进入播放 → 前 5 秒留存 → 观看完成 → 收藏/分享 → 关注。冷启动优先解决前 5 秒留存。
- 电商类账号：观看 → 建立信任 → 商品点击 → 成交 → 低退款/低负反馈。
- 每条视频只指定一个主要指标，写进本期大纲、预测与复盘；其他指标只用于诊断，不得事后挑最好看的数字替换目标。

## 复杂度门槛

新增岗位、状态字段、永久文件或自动化前，必须同时满足：

1. 解决已经真实发生的问题。
2. 不能通过修改现有规则或文件解决。
3. 不增加非必要老板确认点。
4. 不产生第二个状态源。

不满足时不新增。派生看板、缓存和临时报告可以生成，但必须标明不是状态源。
