# 提案师共用策略

> 只保存两个账号共用的判断方法。平台来源、验证顺序和账号门槛见各账号 `skill-base/提案师/选题验证.md`。

## 选题漏斗

```text
外部信号或老板灵感
→ 快速收件
→ 轻诊断
→ 账号专属验证
→ 现在做 / 补证据后做 / 留池 / 淘汰
→ 老板确认选题
→ 大纲（提案师草拟）
→ 老板过目、补充想法或资料、定稿
→ 移交编剧
```

自动发现与正式推荐分开：自动任务只能收集公开候选、保留来源和日期并进入快速收件区，不创建视频、不改变候选状态、不下“值得做”结论。

## 大纲定稿检查点

大纲写完不等于可以移交编剧，中间必须有一次老板过目：

- 提案师草拟大纲后，完整展示给老板，不能只汇报结论就自行判断"证据够了、可以叫编剧"。
- 老板看完会补充自己的想法、真实素材或调整意见；提案师据此修改，直到老板明确确认定稿。
- 编剧写逐字稿的依据是"定稿大纲 + 与老板的对话内容 + 老板新提供的资料"三者合并，不是只靠提案师单方面的证据判断。
- 原因：市场证据（离群账号、门槛）只能证明"这个方向值得做"，不能替代老板对具体素材、个人经历和呈现方式的判断；两层判断都过一遍才能定稿。

## 轻诊断六问

1. **具体人群**：谁会立刻觉得“在说我”？
2. **真实问题**：他在什么时刻遇到什么问题？
3. **可见结果**：看完或购买后能得到什么可展示结果？
4. **账号适配**：是否强化账号定位，而不是只追宽泛热点？
5. **创作者资格**：老板有什么实测、经历、方法、案例或判断可以贡献？
6. **当前时机**：为什么现在做？属于即时、季节还是常青？

结论只用三档：

- **不成立**：缺少清晰人群、真实问题或可见结果。
- **可改造**：需求存在，但角度、证明或账号资产不足。
- **值得验证**：适配账号、可拍且有继续取证价值。

轻诊断不使用精细总分制造虚假确定性。

### "可改造"结论怎么救（方法借鉴自 viral-topic-miner skill，2026-08-03补充）

轻诊断结论为"可改造"时，不能只写"角度/证明/资产不足"就停在原地，按症状直接查表补：

| 症状 | 补什么 |
|---|---|
| 太宽泛，谁都能用 | 补"谁"——收窄到具体人群 |
| 只有热词，没有人味 | 补"什么时候、为什么现在" |
| 太抽象，说不清结果 | 补"看完/做完能得到什么可见结果" |
| 不可拍，只是个观点 | 补具体动作、画面或成品 |
| 像资讯搬运，没有创作者判断 | 补一手实测、失败案例或判断框架 |
| 像广告，产品感太重 | 先讲用户问题和真实使用场景，产品最后出现 |

补完后再按三档强度给出改造方案，不是只有一版："**保守优化**（保留原方向，补清人群/情绪/结果）→ **增强改造**（加实测、失败案例、对比、模板）→ **激进重构**（保留核心价值，换人群或叙事切口重做）"，让老板一眼看出改动幅度，不必自己猜要改多少。

### 标题/钩子话术红线

正式推荐或钩子候选定稿前，逐条检查标题和钩子是否踩了这几条：

- 用"颠覆、封神、必爆、绝了"等词替代真实价值——说不清具体好在哪，就是在喊口号。
- 承诺超过现有证据能撑住的程度。
- 只是热词堆砌，没有具体人群和场景。

命中任意一条，退回"可改造"用上表重新补，不直接用到正式推荐或钩子候选里。

## 选题心理触发三层设计（轻诊断补充，2026-07-22 WIKI补充）

轻诊断六问判断"这个候选值不值得做"，这三层设计判断"同样过了轻诊断的候选，为什么有的更容易火"——曝光本质是潜意识投票，不是理性判断"有没有用"。三层递进、缺一不可：

1. **相关情绪**：这个真实问题会让目标观众产生什么可描述的感受或期待？不得为了强度制造羞耻、焦虑、恐惧或愤怒。
2. **冲突张力**：有没有一种悬而未解的落差——现实和期待的差距、自己和外界的冲突、欲望和满足的冲突。
3. **角色代入**：观众能不能在极短时间内识别"这说的是我"，靠具体人群标签建立代入机制。

这些解释只可作为来源假设。实际提案优先验证真实任务、受众语言、具体处境和可见结果，不把生存焦虑、群体比较或身份压力当成默认流量工具。

可套公式：**爆款选题 = 老问题 + 强情绪 + 强代入感**。给候选定稿前可用自检清单复核：观众看完会有什么情绪？是否触及更大的共性问题？是否让某类人群能代入？是否有反差或悬念？

（与 Jonah Berger STEPPS 模型对照：情绪钩子≈Emotion，角色代入/同类认同≈Social Currency+Public，冲突张力/生存焦虑≈Triggers；STEPPS 另有 Practical Value 清单类内容转发率最高、Stories 主角+困境+转折+转变+邀请参与的故事结构，可作为轻诊断之外的补充视角。）

## 固定来源清单=检查清单

各账号 `skill-base/提案师/选题验证.md` 的"固定来源及职责"表格不是参考资料，是检查清单。2级标准验证或以上，写正式推荐前必须把该账号自己的固定来源表逐行过一遍，明确"用了/跳过+原因"，不能只凭自己想起哪个查哪个——遗漏一个固定来源（比如只查了中文平台、漏了账号规则里明确要求的YouTube/GitHub）跟遗漏一步流程是同一类问题。`research.md` 的"结论速览"区块要有一行"平台覆盖"，逐个标注该账号固定来源是否已覆盖，没覆盖的写明原因。

## 证据分工

| 证据 | 可以回答 | 不能回答 |
|---|---|---|
| 搜索指数 | 是否存在搜索或讨论需求 | 单条视频是否会爆 |
| 平台作品数据 | 某种题材或表达曾引发行动 | 内容是否真实、是否适合本账号 |
| 作者近期基线 | 某条是否跑赢作者常态 | 异常一定由选题造成 |
| 评论与用户讨论 | 用户语言、疑问、反对和未满足需求 | 产品功能或功效是否属实 |
| 官方来源 | 名称、版本、价格、规则、规格和限制 | 平台是否想看、实际体验是否好 |
| 老板实测 | 本账号能否可信证明和展示 | 市场需求规模 |
| 本账号数据 | 什么适合自己的观众 | 外部市场的全部机会 |

事实、外部观点、合理推断和待实测项必须分开记录。

## 算法资料的用法边界

`流量机制学习摘要（原始笔记不随仓库分发；平台事实使用前须查当前官方来源）` 回答"这类内容形式当前是否符合平台分发偏好"（比如2026年抖音收藏率/复访率权重已超过点赞、断更7天有明显衰减），不能回答"这个选题值不值得做"——用法边界与"平台作品数据"一致，纳入证据分工表同一类：能证明"某种表达形式当前被算法偏好"，不能证明"内容真实、适合本账号或选题本身成立"。轻诊断第6问"当前时机"可以参考其中的常青流量/断更阈值判断是否值得赶时间窗口，但结论仍要落在人群、问题、可见结果三项上。

## 小红书搜索排名机制（资料主张，2026-07-21 WIKI补充）

小红书排名不是单靠发布后的自然流量，搜索排名由四个维度加权：内容匹配35%（关键词精准匹配+语义相关+使用场景三层）、账号权重25%（LV1-LV5账号等级）、投放加持20%（投放带动互动数据后系统判定为优质内容、进而提升自然排名，但停投红利只持续约72小时）、互动数据20%（2026年收藏率、完读率的权重已超过点赞率）。

对应SEO四步法：挖词（下拉联想词、搜索结果页关键词、竞品高频词）→ 关键词布局（标题前10字、正文出现3-5次、标签3-5个）→ 长尾词主攻（长尾词转化效率是核心大词的3-5倍）→ 搜推互通（自然搜索和推荐流互相导流）。

背景：约78%的00后用户是"先搜索再决策"，这解释了为什么小红书对内容的专业深度、可读性权重明显高于抖音——写小红书选题和大纲时，标题和正文的关键词布局要当成硬性检查项，不能只顾"好不好看"。

账号权重本身分三层：基础权重（实名、合规历史）、动态权重（近30天内容垂直度需≥70%，近7天内容×3权重、90天前内容×0.3权重衰减）、实时权重（发布后1-3小时的窗口表现）。提案师给账号做选题建议时，可以用这个权重结构解释"为什么突然跳出账号定位的一条视频，会拖累接下来一段时间的整体表现"。

## 五种内容游戏与账号该用什么KPI判断（资料主张，2026-07-21 WIKI补充）

大多数账号策略混乱的根源不是执行力差，而是"参加了A游戏却用B游戏的规则"。判断一条选题/一个账号是否成功之前，先确认它属于哪种游戏，因为KPI完全不同：

1. **全民偶像**（如MrBeast）：话题追求超大众化、跨圈层传播，靠平台广告分成和品牌赞助赚钱。
2. **垂直领域王者**：在特定类目里做到最出名，但类目内要选"该类目里最大众的话题"，广告单价更高因为受众更精准。
3. **直觉型产品带货**：产品一看就懂（零食、衣服），内容负责营造氛围或展示用法，漏斗越大转化越多。
4. **解释型产品带货**：产品需要教育市场（保健品、AI工具、B2B软件），内容以教育为主，核心是命中用户具体痛点或欲望。
5. **权威建立**：靠专业内容建立"这个领域的专家"信任，目标不是粉丝量而是转化率，把人导向私域。

游戏1、2的核心KPI是播放量/粉丝数/互动率，因为流量本身就是钱；游戏3、4、5必须切换成 **$/View**（总收入÷总播放量）或转化率/View——不能看播放量，1000播放带来10个精准潜客，比100万播放零转化更有商业价值。

对提案师意味着：给带货/权威型账号做选题验证或复盘时，"这条播放量不高"不能直接判定为失败，要先确认它玩的是哪种游戏，再套对应KPI；同时警惕最常见的错配——用游戏1的打法卖产品（吸引大量不买单的人）、用游戏3的打法建权威（硬广无人信任）、在游戏5里追求粉丝量而非转化率。

## 逆向工程研究对象的选择原则（资料主张）

研究对标账号时，优先研究粉丝量1万-25万、正在快速成长的中小账号，而不是研究百万粉的顶级大号——顶级大号已经积累了强信任惯性，观众看到就买账，数据会有噪音，不能干净地反映"这条内容/这个选题本身"的效果。这条原则补充在"平台样本判断"的"排除置顶广告"之外，作为选样本时的前置过滤条件。

## 选题灵感来源命中率排序（资料主张，供轻诊断前置参考）

灵感来源按命中率从高到低排序：自己的离群值（自己历史内容中数据异常好的） > 同行离群值 > 其他媒介的离群值（播客/图文/长视频等跨媒介） > 品类新闻 > 同行非离群值（同行的常规表现） > 完全原创。建议自己和同行离群值合计占选题研究时间的80%以上。

可配合的日常动作（Idea Mining）：每两周维护一份10-15个同赛道竞品的观察名单（粉丝1万-100万区间），扫描其近期top 50-100条视频，提取5-7个高频主题，自问"我有没有更好的角度切入同一个需求"，而不是直接照搬对方的选题。

Idea Mining 的具体捞素材渠道（2026-07-22 WIKI补充）：判断一条同行内容值不值得跟拍，关键信号不是博主粉丝量，而是**粉丝少但播放高**（说明是话题本身的势能，不是私域流量撑起来的）；同行离群值最直接的抓手是**去爆款视频评论区找高赞留言**直接拍成选题；小红书另有热点榜、创作中心-创作灵感、千帆 APP/PC 端等官方工具位可直接查。

内容能不能持续起效，还取决于4个不能输的底线条件，提案师给账号定节奏或做复盘时可作参考：保持更新（至少每周3条，理想5-7条）、每条视频都带可衡量的改进假设（不是重复同样的错误）、把流量导入匹配的转化路径（没有转化路径播放量只是爱好）、坚持到位（基本技能通常在第50条视频左右才锁定，多数人在第25条就放弃）。

## 选题生成框架：怎么把灵感变成具体选题（2026-07-22 WIKI补充）

上面解决"从哪找灵感"，这里解决"怎么把灵感造成一句可执行的选题"，两类互补手法：

**维度交叉组合**——拆成至少两个独立维度分别列举再交叉，维度越具体、组合越可控，能批量产出。三种载体选一种顺手的即可，本质相同：九宫格/曼陀罗法（中心写行业，一圈圈往外扩到人群、场景）、思维导图法（先画目标人群，再长出这类人关心的负面事件分支）、表格矩阵法（行业关键词×人群×场景类型做笛卡尔积，扩展性最强）。小红书可用更细的**象限选题法**：从价格定位/时间季节/目标人群/使用场景/节假日活动/需求功能6个象限选2-4个组合（如"学生秋冬平价保湿好物"=人群+季节+价格）。交叉出的词必须转化成一句有画面感的疑问句/陈述句，不是简单拼词。

**单点冲突公式**——不需要交叉维度，一个反差点即可，更适合情感/观点类内容：①"行业+负面最高级"（"差评最多的烧烤店"），落地仍要给真实信息量，不能只是骂人；②"社会规范 vs 个人立场"（"30岁不买房不买车真的错了吗"），比交叉组合更快但不适合强种草/测评类。

**选题复用三法**（可叠加非互斥）：连续剧规划（一开始就计划拆成系列连续更新）、素材膨胀（同一选题隔段时间换观点重讲，核心心法是观众记性短但不能"新瓶装旧酒"被一眼看穿）、格式复用（同话题换形式，教程→避坑指南→对比测评→案例复盘）。

## 平台样本判断

搜索结果只建立候选池，不把排名、高绝对互动、播放/粉丝比直接当成离群结论。

判断相对异常时：

1. 定义同平台、同观众、同问题、同结果承诺的内容机会单元。
2. 优先查看作者最近 10—20 条可比作品，排除置顶、广告、直播切片和不同格式。
3. 用近期可比作品主指标中位数建立基线；没有基线时只能称“高互动候选”。
4. 同时寻找表现普通的同题材反例，拆解差异来自 Topic、核心判断、结果承诺还是包装执行。
5. 只迁移需求、结构和证明方式，不复制原话、经历、画面或整套组件。

只有需要证明“该角度已被平台异常表现支持”时才建立完整基线；AI时效事实、老板原创经验等选题不机械套用离群门槛。

## 三档研究强度与停止条件

使用四档成本预算：

- **0级·收件**：只保存原话和来源，不搜索、不评分、不立项。
- **1级·轻诊断**：只判断是否值得继续。六问得到明确结论即停止。
- **2级·标准验证**：准备选择下一期时使用。需求、适配、证明、时机四项均有足够依据即停止。
- **3级·深度验证**：高制作成本、强事实、正式带货或高合规风险时使用。关键事实、负面证据、适用边界和实测门槛闭环后停止。

证据无法取得时标记缺口，不为凑固定数量无限搜索。老板要求声称“低粉爆款验证”或“跨账号稳定机会”时，仍需至少 3 个独立账号的有效异常样本和 2 个普通反例；不足时降低结论强度。

## 证据投资回报

每次外部查询、打开长文、读取评论或转录视频前，先回答：

1. 这份材料要改变哪个“做 / 补证据 / 留池 / 淘汰”决策？
2. 哪种结果会改变当前判断？
3. 有没有更便宜的元数据、短片段、官方字段或老板实测可以先回答？

无法回答第 1、2 项时不搜索。优先顺序是：已有项目事实 → 元数据或摘要 → 关键片段 → 少量评论 → 完整正文或字幕。原始批量结果保存到临时文件或项目证据文件，只把与关键问题有关的精简字段带入上下文。

连续两轮新增证据都没有改变判断时停止；只有发现新的关键矛盾，才重新定义问题并继续。研究质量以“最低成本取得足以决策的证据”衡量，不以链接、样本或 Token 数量衡量。

## 选题表达与组合

每个候选写清：

- **Topic**：目标观众关心的具体领域。
- **Seed**：一句非显而易见但不过度的核心判断。
- **Substance**：事实、案例、实测和可执行步骤。

最终决策不只问“它值不值得做”，还要问：

- 是否与最近内容过度重复？
- 是否补足当前账号的内容组合？
- 主要目标是曝光、关注、点击还是成交？
- 本期主要实验变量是什么？有哪些已知混杂变量？

## 参考内容与偏好主播

偏好主播池回答“老板喜欢怎样表达”，同赛道样本回答“市场发生了什么”，官方来源回答“事实是否成立”。三者不得混为证据。

偏好主播可用于学习题材敏感度、节奏、案例组织、画面、可信感和价值观；不得因为老板喜欢某主播，就把其观点或数据视为事实。

## 原始证据留档规范

只要一份原始数据被用来支撑"现在做/补证据/留池/淘汰"这个判断，就必须把原始数据本身存进项目，不能只把加工后的结论（倍数、判断、摘要）写进 `research.md`，原始数据本身留在临时目录或干脆不保存。原因：结论可能算错、复核时说不清依据、临时目录会话结束就可能丢失。

**适用范围**（不止参考视频）：

- **作者基线原始抓取**（`user-videos` 之类批量数据）：存进 `01assets/证据原始数据/<作者>_user-videos.<格式>`，并写一份 `README.md` 索引说明每份文件对应哪个候选、用途、采集日期。`research.md` 的证据表格旁注明"原始抓取结果已存档，见 `证据原始数据/`"。
- **参考视频转录**：大纲不能只按风格指南凭空写。选中的候选如果有离群参考视频，写大纲前应挑1-2条做结构拆解（钩子、铺垫、证明方式、结尾手法，具体拆解方法见下方"参考拆解方法论"），而不是直接照抄提案师自己习惯的通用结构。转录全文存进 `01assets/参考转录_<作者>.md`，开头注明来源URL、作者、采集日期、时长、离群倍数（如有）、转录方式、用途说明（仅供参考手法，不得直接照搬原话、经历或比喻），并在 `research.md` 结构拆解小节链接回去。
  - 技术方法：用平台CLI（如 `opencli douyin user-videos <sec_uid> -f json`）取目标视频的可下载链接，注意该链接通常有时效，取到后应尽快使用；用 `agent-reach transcribe <链接或本地文件> -o <输出路径>` 转录；若下载链接过期需重新拉取；若本机音视频处理依赖缺失或损坏导致转录失败，先尝试修复依赖（如 `brew reinstall ffmpeg`），必要时先下载到本地文件再转录。
- **官方事实核验**（WebSearch/WebFetch 结果）：至少在 `research.md` 里保留完整来源链接、采集日期和关键原文引述（不只写结论一句话），让"官方说了什么"可以脱离网页本身被核对；网页可能改版或失效。

`research.md` 因为多轮调研会越写越长，写完后在文档最开头加一个"结论速览"区块（最终选题、时长、状态、大纲文件路径、各节对应内容），方便老板不用翻到决策小节才知道定了什么。

## 参考拆解方法论：对标账号与单条爆款怎么拆（2026-07-22 WIKI补充）

用于"参考视频转录"环节做结构拆解时，先定位自己的短板（表现力/文案/拍摄哪块弱），带着问题去拆才有针对性；新手不建议一上来盯单条爆款，要先退出来看整个账号：

**逻辑层（拆一个账号，四点）**：①定位——能否一句话说清"帮谁解决什么问题"，谁+解决什么问题缺一不可；②内容——发哪几类内容、配比如何，重点看对标账号起号第一个月发了什么（更有借鉴价值）；③变现——广告/带货/卖课，决定学他能不能赚到钱；④增长——靠一条视频"蒙"起来还是持续输出积累，决定自己的增长节奏规划。

**技术层（拆单条爆款，8维度）**：选题（老套路还是蹭热点）、呈现形式（图文/口播/情景剧）、脚本文案（最重要，可再拆叙事逻辑/论证方法/结构/语言风格/情绪钩子/对话对象6个子角度）、拍摄手法和布景、表现力、装造、节奏、标签发布时间。

**文案专项五步拆解法**（8维度的简化聚焦版，配合用）：拆标题（数字/人群/行为/场景/价格等要素）→拆封面（单图/拼图/是否出镜/文字排版）→拆选题（是否戳中受众痛点）→拆文案（开头前5秒、结构是并列式还是总分总、金句句式位置、结尾用引导/种草/煽情/总结哪种）→盘点这条视频的独特之处。

拆解顺序原则：先过逻辑层四点搞清整个账号怎么运作，再拆技术层单条视频，跳过逻辑层直接扎进"这条为什么火"容易学到孤立技巧、不知道放进账号节奏里怎么用。

## 品牌差异化的三条路径（2026-08补充，账号定位/防同质化时用）

回答"整个账号的调性怎么立"，比单条文案怎么写高一个维度：

- **人格拟人：先有魅力人设，再谈功能**——爆款是感性对战理性的胜利，消费者/观众被吸引前只有一秒钟，这一秒靠不了讲道理，只能靠有个性的人格先抓住注意力，功能信息留到后面。人格立住后内容品类可以随便延伸，因为观众记住的是人设不是单一选题的参数。
- **拒绝趋同：所有人都在比参数时，做自己最锋利**——同赛道账号越比越像时，"不从众"本身就是最锋利的差异化武器，不需要在别人的赛道里争第一。
- **可验证真实感：用具体事实代替空洞自夸**——不说"用心做内容"（谁都能说，没法验证），说具体可验证的细节（"拍了六个月才攒够这期素材"）。判断"讲故事"还是"讲鸡汤"的分界线不是有没有情感，是情绪金句后面有没有接一个可验证的具体细节。

这三条最终都要经过编剧`逐字稿结构.领域.md`里的"场景化叙事"才能变成一条具体可用的文案；"可验证真实感"和"卖点提炼五步"第四层"证据支撑"是同一原理。

## 自媒体IP打造方法论：命名、人设与信任升级（2026-08补充，新账号起号阶段用）

无论是靠广告变现的个人博主，还是想借创始人身份提升企业信任的老板，做IP的本质路径都是同一条升级链：**认识 → 信任 → 喜欢 → 爱上**。内容策略要分层设计，不能一上来就追求"被爱上"。

- **起名**：好记顺口 + 信息量足，一个好名字应该让人一句话读出职业定位和性格特征。
- **人设 = 真实部分 + 设计部分**：设计指的是对真实特质的有意识放大和包装，不是凭空造假。核心原则：**人设可以增加，不能颠覆**——后续可以不断叠加新记忆点，但不能出现推翻此前人设根基的行为，否则不是"反差惊喜"而是"人设崩塌"。
- **喜欢 vs 爱上（反常识区分）**：喜欢一个人是喜欢他的优点；爱上一个人往往是爱上他"无伤大雅、不会伤害到别人"的缺点。只展示完美优点的人设容易被喜欢，但很难被真正"爱上"（难获得长期忠诚度），适度暴露真实无害的缺点反而加分。
- **企业主/老板做IP**：诉求分两种，由企业规模阶段决定——追求转化（口播立观点、建立专业权威）或追求品牌影响力（生活化内容，让形象更立体亲和）。

新账号做定位诊断（轻诊断六问）时，起名和人设两步属于前置动作，人设一旦对外呈现就纳入"可增加不可颠覆"的原则约束后续所有选题判断。

## 短视频爆款判断公式与系列化打法（2026-08补充）

一条视频成为爆款需同时满足四个必要条件：观众看得懂内容、话题体量足够大、满足观众点开平台的诉求之一（调动情绪或获得信息）、能引发互动（评论转发，不只是点赞收藏）。

**爆款三种类型**：万古同悲型（极致共情，强度排序：家国苍生>社会冷暖>生死离别>人生失意>壮志豪情>父母子女>男女情爱）、惊世骇俗型（极致反差或极致震撼）、打破节奏型（信息流整体快节奏时，突然安静或慢下来反而截停划走动作）。

**爆款视频 vs 爆款系列：涨粉效率的分野**——起号阶段真正该盯的是涨粉量而不是播放量，很多账号播放量高但涨粉少，问题出在选错了爆款类型。能带来涨粉的三类：人设型（观众通过思维认知感到与博主"兼容"）、才华展示型（可持续输出的技能内容）、有延续感的攻略型（单次性攻略用户看完收藏就走，只有系列化攻略才涨粉）。跟热点做的爆款视频约80%对涨粉没意义，除非内容展示的核心是博主本人。

**核心洞察**：普通爆款需要观众自己从内容里"判断"出博主隐形价值才会关注，中间存在判断成本；**爆款系列直接省掉这个判断成本**，把价值明示给观众。三种做出系列感的方法：剧情系列（构建人物IP和世界观，单期就透露宏大故事框架）、提升系列（用"挑战/多少期/多少天/系统"制造延续感）、探索系列（用未完结叙事或明确数字进度条制造延续感）。

对提案师和复盘员的可执行提醒：判断一条选题该不该做系列化，先问"观众看完这条，会不会自然产生'想看后续'的预期"，而不是发完一条再临时决定要不要接着做。
