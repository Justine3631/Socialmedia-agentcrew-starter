## ChatCut 工作流（操作级）

1. **创建项目** — 名称：<账号>-<视频短标题>
2. **导入素材** — `04media/` + 实拍 + 录屏 → asset-import
3. **搭建时间线** — 按 03outputs/分镜.md 的顺序
   - Track 1：口播主轨（实拍素材）
   - Track 2：B-roll / 图片（需要配画面的位置）
   - Track 3：AI生成片段（如有）
   - 音频轨1：配音（导入或调用TTS）
   - 音频轨2：背景音乐
4. **精修** — 切多余、调时长、加花字
5. **确认** — 给老板编辑器链接预览
6. **导出** — 成品放 06video/

## 口播剪辑节奏

- 只删不承担语义或语气作用的口癖；“然后”等顺序词、转折词、强调和自然呼吸不能仅因命中词表就删除
- 句与句之间留 0.3-0.5 秒间隙
- 强调重点前留 0.3 秒停顿
- 不把所有停顿剪光；保留能强化重点、思考感和可信度的停顿
- 多条 take 中优先选择句尾不无意识掉音、状态自然且有能量的版本
- 音频精修同时检查重点词、句尾响度和语气，不能只检查字幕正确

上述秒数只是起始参考，最终以说话自然、信息能被吸收和账号风格为准。

结构剪辑锁定后，逐切口回听词头、词尾、呼吸和底噪连续性。后端提供音频微交叉淡化时用于消除硬切爆音，不跨淡化吞掉辅音或制造双重人声；ChatCut 的 `smooth_audio` 仅在当前工具实际存在时使用，结构重排后需重新检查。J-cut / L-cut 只在画面切换需要声音桥接时使用，真人同期嘴型不能被无意错开。

## B-roll 使用

- B-roll 不要贯穿全片，只在需要时插
- 时长 = 口播内容能支撑的时间
- 切换时画面要有逻辑关联

## 背景音乐

- 有口播时：音量 10-15%，低频为主
- 无口播纯展示：音量 30-50%
- 结尾升华：渐强

上述百分比只是剪辑后端的起始参考，最终以人声清楚、动作落点可辨和平台响度 QA 为准，不用固定百分比替代混音判断。

## 高级动效系统

### 默认转场基线：先极简，再升级

本节整套高级动效系统只用于分镜.md逐镜明确标注"重点/产品级"的镜头。**未标注的镜头默认走极简转场**（硬切为主，统一一种极简过渡，如4帧淡入淡出），剪辑师不得自行判断"这里可以做复杂一点"而升级复杂度。默认全片套用本节的三段式装框/错峰/硬切运动匹配等，是转场"太快、看不懂逻辑"最常见的成因——先把大部分镜头做简单、做清楚，再把预算花在真正需要的少数重点镜头上。

### 先设计运动，再选工具

动效服务分镜中的动作动词：展开、聚焦、组装、转化、验证、收束。没有语义动作的装饰不做；同一画面只保留一个主动作，次级元素延迟或弱响应。

禁止把统一的“弹入＋缩放”套给所有元素。每个重点镜头按以下顺序制作：

1. 主焦点先建立起始状态和运动路线。
2. 次级元素按依赖关系错峰响应。
3. 必要时加入短预备或轻微越位。
4. 主体落稳后保留结果观看时间。
5. 声音落在接触、锁定、完成或验证动作，不机械贴剪辑点。

### 起始运动预设

以下是起始范围，不是必须命中的固定参数：

| 用途 | 持续时间 | 运动要求 |
|---|---:|---|
| UI 聚焦 | 320–480ms | 快速启动、柔和落稳；背景弱化，目标清楚，不弹跳 |
| 纸片/卡片组装 | 380–600ms | 元素错峰 60–110ms；允许轻微越位后落稳 |
| 镜头推进 | 800–1400ms | 缓入缓出；推进期间主目标持续可读 |
| 结果击中 | 180–260ms | 前置 80–120ms 收声或预备；结果保持 600–1000ms |
| 机械/打字机 | 按结构分段 | 分阶段卡位，不做连续漂移 |
| 纸拼贴逐格 | 最终按项目帧率输出 | 运动可模拟 8–12fps 的逐格触感；不得使用渲染时随机抖动 |

不同材质使用不同运动身份：UI 精确、纸张有摩擦和落位、真人自然、镜头连续。不要让 UI、纸片、字幕和真人都使用同一弹簧曲线。

### 按理解任务选择动效

先写“观众这时要看懂什么”，再从下表选最小表达；现有 motion-kit 或 HyperFrames 原子规则能完成时不新建组件。高级运动仍只用于分镜明确标注的重点镜头。

| 理解任务 | 最小表达 | 验收重点 |
|---|---|---|
| 操作顺序 | 当前步骤高亮，完成后才进入下一步 | 观众能辨认当前步骤和完成状态 |
| 前后对比 | 固定对象位置、尺度和标签，只改变被比较项 | 差异来自内容，不来自构图跳变 |
| 因果关系 | 原因先出现，再呈现路径和结果 | 顺序不暗示未经证实的因果；相关关系明确标为相关 |
| 抽象转化 | 用具体物件演示一次状态变化，落稳后给结论 | 比喻不冒充实际操作或结果证据 |

每个重点镜头明确入场焦点、连续变化的对象、落稳终态和阅读保持。需要阅读的文字落稳后不再为装饰漂移；保持时长随字数、截图复杂度和口播判断，不机械套固定秒数。字体、间距、色板和线条沿用账号风格圣经，避免用更多运动补偿排版问题。

### 顺畅与可读验收

- 正常速度连续看镜头及其前后切口：视线能从旧焦点找到新焦点，运动方向、主体尺度和声音有合理衔接。
- 同屏一个主要观看任务；动效、标题、字幕不在同一时刻争夺注意力。讲解复杂时先减少并行动作，再考虑减速。
- 在目标手机显示尺寸检查真实截图、字号和字幕；完整读懂后才进入下一步。放大窗口可读不能代替手机检查。
- 静帧用于查布局，逐帧用于查闪帧和边界；两者均不能代替正常速度播放。慢放仅帮助定位，最终观感以正常速度为准。

### 参考片转译：只学语法，不复制品牌

参考片必须先拆成节奏、空间、材质、声音和信息层级，再转译为原创镜头。禁止复制 Logo、品牌资产、原文案、具体构图、原音乐或原音效素材。

先标出三种时间状态：

1. **安静定格**：单主体或一句话保持约 0.8–1.8 秒，让观众吸收结果。
2. **极短精准动作**：聚焦、落位、装框、标签补充等动作约 0.2–0.7 秒。
3. **快速蒙太奇**：优先硬切；用中心锚点、运动方向、主体尺度、固定标签或跨切尾音保持连续。

不要让全片始终匀速“丝滑”。高级感来自静止、突发、密集、留白的能量反差。高复杂度动作后必须安排减法；连续两段高密度内容之间至少给一次可辨认的呼吸或单主体状态。

### 三段式装框

把屏幕、录屏或生成内容从“内容本身”转化为版面物件时，分三段执行：

```text
全屏内容
  收边形成边框
  缩小成为桌面/版面卡片
  新主体从释放出的空间接力进入
```

- 每段只完成一个空间任务，起始参考 0.22–0.55 秒。
- 前一段进入减速尾部后，下一段才能启动。
- 不同时执行缩放、旋转、换内容、标签出现四件事。
- 新主体先完成 60–80% 位移，标签或状态再迟 3–8 帧出现。
- 快切段中的标签尽量固定位置，只命名能力，不重复完整画面信息。

### 硬切运动匹配

硬切不是低级转场。前后镜头至少锁定以下两项，切口即可保持流畅：

- 主体运动方向一致。
- 视觉重心或主体尺度接近。
- 标签、边框或交互锚点位置稳定。
- 亮度和色温有计划地连续，或用明确明暗反差断句。
- 声音尾音跨过切点约 100–300ms。

若前后镜头没有可匹配关系，先插入单主体、留白页或材质突变作为章节断句，不用通用 whoosh 掩盖结构问题。

### 屏幕与竖屏的原创适配

- 屏幕操作可先全屏保证可读，再装框进入竖屏中央主舞台。
- 背景状态可以变化，但光标、输入框、结果区等核心交互锚点不能同时漂移。
- 9:16 中央约 55–70% 承担主信息；边缘只放可裁切的纸片、标签或装饰。
- 内容展示先单项，再用拼贴总览收束；不要先给总览后重复逐项介绍。
- 结尾可用“语义内容—短句—字符—符号”逐级减法收束，但一条视频只使用一次。

### 竖屏空间

9:16 屏幕教程以中央约 60% 作为主舞台；上方放章节/任务，下方放状态/结论，左右边缘只露部分纸片、标签或道具。前景快、中景正常、背景慢形成视差。关键 UI、光标、字幕和结果必须留在平台主要安全区。

## 声音设计系统

按功能组织四类声音，不按“哪里空就加音效”处理：

1. **音乐底**：负责章节和情绪；重点前可降密度或短暂抽空。
2. **材质声**：纸张、笔触、胶带、翻页、机械结构。
3. **交互声**：点击、输入、确认、扫描、加载。
4. **结果声**：柔和 impact、低频落点或短 tonal hit。

一个重要动作最多一个主音效。峰值对准物体接触、锁定、完成或验证帧；同一种物体保持相似声音身份。禁止每次切镜都加 whoosh，禁止用宣传片式重低音掩盖口播。参考片只吸收声音层次、留白和同步方式，不复制原音乐或响度。

### 丝滑声音的章节组织

“丝滑”不等于铺满。声音按章节组织为四层：

1. **中心床**：稳定、低密度、以中间声像为主，连接同一章节。
2. **材质层**：纸张、笔触、键盘、机械结构等，与可见物体身份绑定。
3. **宽瞬态**：只在章节转换、空间快速展开或装框完成时短暂向左右打开。
4. **结果音**：发送、完成、验证、符号收束时使用短 tonal hit 或轻 impact。

执行规则：

- 高价值转场前先让音乐或环境床降低约 3–6dB、收窄频谱，必要时短暂抽空。
- 快切段由同一节奏床连接，只给少数关键动作触点，不逐切镜配 whoosh。
- 音效峰值落在接触、锁定、完成或验证帧附近；允许落点后 0–2 帧，尾音跨切。
- 持续层保持较窄、较居中；立体声宽度留给少数转场瞬态，避免全片一直“很宽”。
- 一个动作优先选最能说明其材质或结果的一层；只有重点动作才组合 2–3 层。
- 章节结束和全片结尾主动减法，通常应比中段更轻。
- 纯合成噪声不能代替与物体匹配的 Foley；素材必须原创或许可清楚。

### 联合样片验收

制作预览卡的 10–15 秒视觉与运动样片不带配乐/音效，保留素材已有口播；从本片实际需要的动作中取代表镜头，不为凑检查项加入装框、错峰或复杂转场。验证：

- 主体、状态变化、落稳与阅读保持可辨认；复杂动作后有吸收信息的时间。
- 适用时检查装框、主体与标签错峰、运动匹配硬切或章节断句。
- 正常速度连续播放与手机显示尺寸均清楚；静音后仍能辨认主动作。

声音在完整候选统一验收，不作为无配乐/音效预览卡的通过条件：先闭眼听人声、切口、音乐和适用的声音事件，再声画合看。声音峰值与可见动作对齐；没有相应材质、章节或结果动作时，不为凑声音层数添加音效。

- 不要整段复制口播
- 花字出现和消失要干净利落

## 可选资料模型：多巴胺阶梯

> 仅在项目明确采用该来源模型时参考；不是剪辑默认检查项。默认仍检查理解成本、信息推进和结果兑现。

- L1 刺激：开场先让主题或结果清楚；是否快切按内容测试，不设“0.5 秒必须变化”的硬规则
- L2-L3 预期：通过剪辑维持好奇心，信息密集段贴紧
- L4 验证：答案揭晓时可通过音效、特写或对比强化，但不能用效果替代真实结果

## 剪辑环境预检

通用检查：

- 项目比例、帧率、文件命名和代理设置是否正确。
- 素材路径是否稳定，是否存在媒体丢失或需要重链。
- 磁盘空间、缓存空间和后台应用是否会影响剪辑。
- 快捷键是否符合当前后端与操作者习惯。

### 剪映个人操作备忘（仅供老板手动使用）

- 可设置适合自己的快捷键预设。
- 网络异常先使用剪映自带检测；媒体丢失时重链原文件。
- 清缓存属于显式维护动作，先确认不会误删仍需使用的内容。
- 云草稿同步涉及素材隐私、版权、账号空间和网络成本，不自动上传。
- 剪映不进入工作台正式剪辑后端和备用后端路由；员工只在老板明确要自己用剪映操作时引用这段备忘。
- 这份资料目前只到初始化与排障，不足以替代通用剪辑方法、ChatCut 路由或项目审核。
