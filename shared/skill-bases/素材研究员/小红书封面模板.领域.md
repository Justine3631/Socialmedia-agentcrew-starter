# 小红书封面模板.领域.md

> 小红书适配版的可选封面方法，不是账号默认审美。
>
> 方法参考：[atutun-xhs-cover-v2](https://github.com/panggungunvibe/atutun-xhs-cover-v2)，采集于 2026-07-16。仓库未见明确 LICENSE，本文件只保留经工作台边界重写后的方法，不复制原 Skill 正文或模板。

## 启用条件

仅在平台计划包含小红书、`publish-pack.md` 指定小红书适配，或老板明确要求时启用。先完成抖音主版，再重新适配小红书；不得只裁切或拉伸抖音封面。

它只负责视觉方案：

- 标题与承诺归编剧，以 `publish-pack.md` 为准。
- 视觉旋钮和拍摄可行性服从导演、账号配置与当前分镜。
- 实际出图默认先走 `xhs-cover`；不可用时才降级到 `imagegen` 并记录原因。成品与生成信息由素材研究员归档。
- AI 生成图不能替代产品实物、官方界面、资质、真实体验或数据证据。

## 输入与缺口处理

按以下顺序读取，不重复询问已存在的信息：

1. `publish-pack.md`：已确认标题、封面承诺、画面方向。
2. 分镜和 `shot-checklist.md`：人物动作、产品姿势、录屏或结果图。
3. 当前项目素材：人物参考、产品实拍、软件截图、结果证明。
4. 账号既有封面或配置：字体感、标题主色、强调色、描边逻辑。

人物不是硬门槛。没有合适人物参考时，优先采用产品、界面、结果图或手部实拍，不凭空生成“通用博主”。仍缺的信息最多归纳为：主体参考、证明素材、固定配色；标准模式一次问完，快速模式合并到开拍前确认点。

## 统一构图规则

- 默认输出 3:4 竖版；横版需要重新构图，不能直接裁切或拉伸。
- 核心元素最多 3 个：短标题、主体、一个证明元素。
- 标题使用编剧确认的原文，主标题优先短句；副标题和清单只在能增加理解时保留。
- 人物、产品或关键结果不得被文字遮挡；所有重要信息避开平台 UI 安全区。
- 高对比、大字、描边、箭头和贴纸都是可选手段，不默认叠满。
- 配色优先继承账号历史；没有固定配色时，根据主体选择高对比方案，不机械套用黄色。
- 封面必须用画面证明标题承诺，而不只是重复标题或制造夸张情绪。

## 八类构图

| 构图 | 适用内容 | 画面骨架 | 必需证明 |
|---|---|---|---|
| 强钩子大字 | 经验公开、教程入口 | 上方短标题 + 中下主体 | 结果、界面或真实场景 |
| 核心词块 | 强观点、单一概念 | 2-4 个词块围绕主体 | 一个能解释概念的图形或实物 |
| 小白问答 | 概念解释、避坑 | 问题标题 + 人物/界面 + 简短答案 | 正确界面或例子 |
| 教程清单 | 安装、部署、操作 | 标题 + 主体 + 3项以内步骤/收益 | 关键步骤或完成结果 |
| 测评对比 | 工具、产品横评 | 大数字/结论 + 对比主体 | 真实产品、界面或评价维度 |
| 生活种草 | 体验、好物推荐 | 生活化主体 + 短标题 + 使用场景 | 实拍产品与真实使用状态 |
| 工具拼贴 | 工具组合、工作流 | 主体 + 2-3张卡片 + 分段标题 | 真实截图或工具关系 |
| 深色工作流 | 效率方法、流程公开 | 深色背景 + 流程主体 + 收益短句 | 可辨认的真实流程或结果 |

选择构图时先匹配内容类型和证据，再考虑风格；不得为了套模板伪造数字、清单、产品卡片或工具 Logo。

## 出图与复核

用 `imagegen` 时明确标注每张输入图的角色：人物参考、编辑目标、产品/界面证明或配色参考。首轮只生成一个 3:4 方案；老板要求比较时再生成差异明确的版本，不做只有颜色微调的伪 A/B。

交付前检查：

- 比例与安全区正确，手机缩略图下一眼可读。
- 人脸、身体、手部、产品和界面没有明显变形或错认。
- 标题与 `publish-pack.md` 完全一致，中文无错字、漏字或多字。
- 主体、标题和证明元素形成单一视线路径，没有超过 3 个核心元素。
- 小红书版本是重新构图的适配版，不是抖音主版的机械复用。
- 带货封面没有把 AI 生成画面当成商品证据，也没有扩大商品功效承诺。

通过后保存为 `<current_video>/04media/cover-xhs.jpg`，并在 `asset-manifest.md` 记录参考素材、生成方式、日期和版本。未通过则只针对一个明确问题重做；无法实际出图时保存 `cover-xhs-spec.md`。
