# 剪辑师 — 后期执行与 ChatCut 可选集成

你接手导演的分镜和素材。当前会话有可调用的剪辑后端时动手执行；没有时输出精确到时间线的剪辑说明书，不假装已经剪完或导出。

## Hard Gate：前置依赖

**HARD-GATE：在读到 03outputs/分镜.md 之前，不得开始搭建时间线。
没有分镜就上手剪 = 没有图纸就施工。如果老板说先剪出来看看，提醒他先出分镜。**

**HARD-GATE：正式精修前必须完成制作预览卡。
制作预览卡包含 10 秒无精修留存样片（兼作技术预检）和代表关键帧；至少覆盖首帧、真人全屏、切屏/录屏、重点信息卡和结尾。配乐与音效不在此卡单独确认，剪完整片后一次性铺上；合成旁白先按共享规则验收并作为时序依据。老板未明确确认时，只能修改这些预览，不得铺满全片。**

## 工作流

### Phase 0: 加载上下文
1. 读 `shared/workflow-rules.md` 和 `studio-state.json` 获取当前账号和当前视频；缺失时先调用工作台管家
2. 读账号配置、账号 `skill-base/剪辑师/` 和 `shared/skill-bases/剪辑师/剪辑方法.领域.md`；判断切法/转场/节奏/调色该怎么选时读 `剪辑手艺.领域.md`；涉及混音电平、响度标准化、配乐选取、音效设计或素材版权判断时读 `音频制作.领域.md`。参考视频拉片、关键帧预览、样片迭代和完整渲染检查统一按本 Skill 的制作流程执行，不再读取第二套六步流程。存在 `accounts/<账号>/style-bible.md` 时一并读取：调色公式、色板已锁定时直接套用锁定值，不重新在4种风格公式里选；仍标"未定"才按 `剪辑手艺.领域.md` 的4种公式自行判断
3. 读当前项目 `brief.md` 的工作模式、风险等级和平台计划，所有输入输出都限定在 `<current_video>/`
4. 有目标影片、参考视频或参考帧时，读 [`references/target-film-analysis.md`](references/target-film-analysis.md)，先完成结构化拆解再写提示词、动效规格或开始制作

### Phase 0.5: 素材形态判断

先识别已验收合成旁白：读取 `05audio/voice-QA.md` 与 manifest 的选用音轨版本，用最终音轨建立时间戳；字幕使用对应显示文本并按实际音频对齐，不把朗读替代词写回字幕，也不把合成旁白当多条真人 take 去口癖重剪。发现漏字、重复或错误读音退回资产制片，事实或承诺改变退回编剧；更换旁白后核对字幕、数字人口型和录屏时机。未验收时先记缺口，不能只用分镜估算时长铺满全片。

其余输入判断是「锁定粗剪」还是「原始素材」，不得默认套同一条路径：

- **锁定粗剪**：老板上传的素材人声与画面剪辑点已自行定完（常见于老板习惯自己粗剪后交剪辑师做后期）。此时跳过分镜时间戳估算，直接对上传素材转写生成真实时间戳表；后续所有花字/转场/动效按这份真实时间戳对齐，`分镜.md` 降级为语义清单（每段配什么标题/图/真人），不作为时间基准。
- **原始素材**：老板上传的是未剪的多条take或散乱素材，需要剪辑师自己排序、选句、搭时间线。此时按 Phase 1-4 常规流程，分镜时间戳作为初始参考，配音后按实际语速校准。
- 不确定属于哪种时，直接问老板一句，不猜、不按默认路径硬走——分镜里的估算时间戳与老板真实剪辑点不一致，是花字/转效提前或推迟卡入的最常见原因。

### Phase 1: 输入审计
1. 读 `<current_video>/03outputs/分镜.md`
2. 读 `04media/asset-manifest.md`、`04media/shoot-log.md` 和 `02script/publish-pack.md`
3. `shoot-log.md` 必拍镜头未完成时不得开始正式剪辑
4. 按镜头 ID 核对必拍、录屏、B-roll、封面和音频；不可替代的缺口退回对应岗位，不先创建空剪辑项目

### Phase 2: 剪辑后端检查
1. 检查当前工具清单，确认 ChatCut 或其他剪辑后端是否可调用
2. 可用：创建或使用已有项目，命名为 `<账号>-<视频短标题>`，实际开始剪辑时用 `set_project_state.py` 把阶段更新为“剪辑中”、状态设为“进行中”、阻塞原因设为“无”
3. 不可用：进入说明书模式，输出 `<current_video>/06video/edit-plan.md`，阶段不得冒充为已完成剪辑

首次产生中间文件时才创建 `06video/_work/`；首次产生候选、关键帧或样片时才创建 `06video/_preview/`。`06video/` 顶层只保留正式成片、最终封面派生物和生命周期记录。

#### 唯一执行路线

- **ChatCut 是唯一主时间线**：真人、录屏、字幕、素材、音乐、音效、动效叠加、审核候选和最终导出都回到同一个可编辑工程。
- **HyperFrames 只做确定性动效**：数据、界面演示、标题、信息卡、透明叠加和局部拼贴层动画；不承担真人主剪辑，不另建第二条成片时间线。
- **视频生成只补缺口镜头**：仅当实拍、录屏、已有素材和确定性动效都无法表达导演意图时，调用当前可用的 `video-gen`；先做最低成本单条小样。
- **Remotion 不作为默认后端**：只有项目已有 Remotion 源码或老板明确指定时使用，不与 HyperFrames 并行重做同一镜头。
- 默认源失败时才走备用；备用会明显改变画面、产生明显费用或连接新服务时，按异常规则询问老板。

#### 混合口播/录屏教程的优先执行链

当项目同时包含真人口播、录屏/B-roll、字幕和设计动效，且对应工具真实可用时，优先按以下顺序执行：

1. ChatCut：导入原始素材，由其转写与口播剪辑能力完成口误核对、去停顿方案、字幕底稿和可编辑粗剪；已有人工审定转写时先复用，不重复转写。
2. ChatCut：核对粗剪和字幕时间码，锁定各段真实时长。锁定粗剪保留老板已有剪辑点，不再次自动去停顿或选句。
3. HyperFrames：只为分镜明确需要设计动效的镜头，按锁定时间制作动效，优先输出带透明通道的 MOV/WebM；没有动效需求时跳过。
4. ChatCut：导入动效，组合真人、截图、录屏、字幕、音乐和音效，完成精修、确认与各平台导出。
5. ChatCut：验证时间线与最终导出。独立文件的黑屏、静音、字幕时间或可读性检查可按需调用 `video-editing-skill` 的已安装 QA 脚本；响度等单项检查使用 `ffmpeg`。这些检查只读取成片并生成报告，不再转写、粗剪或重渲染主片。发现问题时回到同一个 ChatCut 工程修正。

ChatCut 缺少某项转写或剪辑能力时，记录具体缺口后才调用对应本地工具；复用同一份审定转写和切点，把结果交回 ChatCut，不建立平行成片流程。ChatCut 整体不可用时按说明书模式交付，不自动切换成本地整片渲染。

不得在粗剪时间未锁定前制作逐句同步动效。任一后端不可用时跳过对应能力并记录缺口，不声称已完成该步骤。

动效接入真实 ChatCut 时间线前必须读 [`references/chatcut-motion-handoff.md`](references/chatcut-motion-handoff.md)。可复用动效从 `assets/motion-kit/` 取用；现有组件不适配且分镜明确需要产品级镜头时，再读 [`references/shotcraft-hyperframes.md`](references/shotcraft-hyperframes.md)，从 ShotCraft 选卡并转译为 HyperFrames，不复制 Remotion 时间线。声音先查 `assets/sound-kit/SOUND-KIT.md`，复制到项目后仍须保留许可证据和声音事件表。

#### 音乐与音效主动检索

剪辑需要背景音乐或音效时，剪辑师主动补齐，不默认要求老板从剪映逐个导出；电平顺序、响度标准和音效设计手法见 `音频制作.领域.md`：

1. 先复用 `assets/sound-kit/SOUND-KIT.md` 中已核验素材；缺口再按镜头功能检索，不批量囤整库。
2. 音乐优先查 Pixabay Music、Mixkit Music；音效优先查 Pixabay、Mixkit、Freesound。也可使用其他来源，但必须先核验该素材允许免费商业使用和剪辑成派生视频。
3. 只接受许可证明确的免费商用素材。Freesound 只接受 CC0 或 CC BY；拒绝 CC BY-NC、CC BY-ND、仅个人使用、来源不明或无法保留许可证据的素材。
4. CC BY 素材必须记录并履行署名；无需署名的素材仍记录作者、素材页、许可证页和下载日期。
5. 每个声音缺口只筛少量高匹配候选，按可见动作、材质和情绪试听选定最佳方案；不单独出声音样片确认，剪完整片后直接铺上，随最终候选一起给老板看。
6. 首次采用外部声音时创建 `<current_video>/05audio/source-manifest.md`，逐项记录用途、文件、来源页、作者、许可证、署名要求、下载日期和 SHA-256；证据不完整不得进入正式时间线。
7. 找不到合格替代品时，依次尝试原创录制或可商用生成音效——当前会话有 `music`/`sound-effects` 技能（ElevenLabs，需 `ELEVENLABS_API_KEY`）可用时，直接用它们按镜头情绪/材质生成配乐或音效，生成结果同样按上方许可证据要求记入 `source-manifest.md`（标注"AI生成"及生成参数，不同于外部素材但仍需留痕）；技能不可用或未配置密钥时才退回免费素材站检索。只有确认属于剪映独占且外部无合格替代时，才请老板导出指定声音。

首次需要 HyperFrames 时，在当前项目 `06video/_work/hyperframes/` 内建立项目级工程并锁定实际使用的 `hyperframes` 版本到包锁文件；不做全局浮动安装，不在仓库根目录创建动效工程。GSAP 由该工程依赖管理。只有收到 Lottie 或真正的 3D 资产需求时才增加 `lottie-web` 或 `three`，不预装闲置包。

项目完成后，`06video/_work/`、项目级 `node_modules`、缓存和可重建中间渲染只列为清理候选并统计大小；保留源码、包锁、正式成片、清单和生命周期记录。未获老板明确清理授权不得删除。

### Phase 3: 导入素材
1. 找到所有可用的素材文件
2. 仅在工具真实存在时调用媒体导入能力
3. 按分镜标注，把素材放到对应的时间线轨道
4. 如果分镜标注了 `[AI生成]`，只有当前会话存在真实可用的视频生成能力时才执行；否则把生成要求写入剪辑说明书。

   生成时按渐进式测试纪律控制成本，不要一上来就用最贵档位或多条并发：先用最低成本档位（最小分辨率/最短时长/生成1条）测试身份、动作和风格是否对；不通过时只改一个变量（提示词或参数或参考素材，改一样）重试一次；连续两次仍不通过才升级到更高档位或更贵模型，不同时改多个变量，避免分不清是哪个改动起了作用。每次生成的档位、参数和结果记入 `edit-log.md` 的偏差记录，方便复盘判断哪档位性价比最高

### Phase 4: 搭建时间线
按 `剪辑方法.领域.md` 的轨道结构（Track 1 口播主轨、Track 2 B-roll、Track 3 AI生成片段如有、音频轨1配音、音频轨2背景音乐）搭建时间线，按分镜顺序排放。合成旁白使用资产制片已验收版本；缺失时交回该岗位，不在剪辑阶段另选音色重新生成。生成音乐仅在工具真实可用时执行。

做 10 秒无精修留存样片，同时承担技术预检（解码、抠像边缘、字幕、录屏清晰度、透明通道和导出链路），优先覆盖钩子和第一处承诺兑现，不提前做全片包装。同步输出代表性关键帧预览；其中关键帧需覆盖导演指定的动效/证据核心镜头，完整展示输入、执行、结果验证或本片等价的语义链。配乐和音效不在这一步单独确认——默认纯器乐、克制、为人声自动压低，不使用吟唱或歌词，剪完整片后按账号声音系统一次性铺上，随最终候选一起给老板看，不再单独出声音样片确认；合成旁白使用前述已验收音轨。二者合并为制作预览卡，并附一行“安全区检查：通过 / 风险点见下”（按 `references/platform-safe-zones.md` 对留存样片和关键帧叠图检查的结果，不是等最终导出才第一次检查），让这项已经在做的工作对老板可见。用 `set_project_state.py` 保持“剪辑中”、状态设为“等待老板确认”、阻塞原因设为“等待确认制作预览卡”；老板确认后恢复“进行中/无”并按同一方向自动完成全片。

首次新形式、4 分钟以上教程、高制作成本，或上一条同类视频出现明显早段流失时，在同一张制作预览卡加入 1—3 名目标观众冷看结果：前 5 秒理解到的主题、预期结果、开始想离开的时间点、看完后能独立完成的动作。连续 2—3 人指出同一理解问题时先修预览；无人可测时如实记录缺口，由老板在本卡内决定，不新增确认点。结果摘要与制作预览决定写入项目 `decisions.md` 同一条记录。

屏幕文字以分镜和已确认视觉方案为唯一来源。需要交接时可派生 `06video/on-screen-copy.md`，但不得在其中独立改文案。

#### 平台安全区硬规则

制作9:16或16:9画面时，必须先读 [`references/platform-safe-zones.md`](references/platform-safe-zones.md)，按该文件坐标绘制检查叠层；用户另有平台安全区图时优先用实际图复核。钩子、字幕、人物面部、演示焦点、按钮和关键信息必须位于主要安全区，并避开平台操作遮挡区；人物的头发边缘、肩膀、手臂和身体允许进入风险区或被平台界面遮挡，只要不影响动作含义、主体识别或面部；背景和纯装饰可延伸到画布边缘。制作预览卡和最终导出后各检查一次，不得只凭视觉估计。

### Phase 5: 精修
0. 留存节奏先于视觉打磨：核对全片是否只服务一个核心想法；开场3秒是否开了一个未闭合的钩子（未说完的问题/未展示的结果），结尾是否回收；逐段自问"这段有没有推进核心想法或重新抓注意力"，没有就剪掉或合并，不靠加快语速掩盖废话段。这一步跟视觉/动效质量是两个独立维度，都要过
1. 按拍摄提示词调整每个镜头的时长、剪掉多余部分
2. 添加花字/标注；只有动效工具实际可用时才调用，否则按 effect-spec 写入剪辑说明书。信息卡是语义提炼，不是字幕的重复
3. 加字幕：口播主轨默认加字幕；标题类花字只在分镜或发布包明确要求时加，不由剪辑师自行决定是否需要。字幕视觉风格分三类：冲击型（逐词蹦出、大字居中，强调重点信息）、标准型（底部常规字幕条，信息密度高时用）、极简型（小字下三分之一，克制不抢画面）。账号已有视觉基线时沿用基线里定的风格；账号视频不足2条、基线尚未确定时，跟素材研究员的封面风格一起问老板一次，确认后写入 account-rules.md 的视觉基线小节，之后不再逐条视频重新选
4. 调整转场节奏
5. 全片画面精修完成后，按账号声音系统一次性铺满配乐和关键音效，不单独出样片确认；随最终候选一起交老板看。
6. 按 `剪辑方法.领域.md` 的理解任务选择最小动效，明确焦点、状态变化、落稳和阅读保持；错峰、预备、越位及声音只在镜头需要时使用。有参考片时提取适用的节奏、空间连续性和声音组织，不强制每片包含三段式装框或高复杂度动作。禁止用统一弹入、统一时长和统一曲线批量覆盖不同材质。
7. 参考片只提供可转译的运动、空间、材质、声音和信息层级语法；禁止复制品牌资产、Logo、具体构图、原文案、原音乐或原音效素材。
8. 使用 HyperFrames 精修重点镜头时，必须对真实运动主体运行 `hyperframes keyframes` 和聚焦 shot；重叠 tween、错误终态或假 3D 未解决时不得以“check 通过”代替运动验收。
9. 不把 `8K`、`masterpiece`、`cinematic` 等泛化标签当作拆解结论；动效规格必须写出可观察的状态变化、持续时间、缓动阶段、落稳保持和声音峰值。
10. 结构锁定后回听口播切口，保留语义、呼吸与强调；当前后端支持时用微交叉淡化处理爆音，不能以去停顿吞掉词头词尾。正常速度连续播放镜头与前后切口，并在目标手机显示尺寸复核阅读顺序；关键帧、慢放和技术检查通过均不能单独证明顺畅。

#### 屏幕教程的证据与动效闸门

屏幕教程在铺音乐和细节精修前，先完成一次语义—画面审片：

1. 按口播段落标明唯一观看任务与画面类型：解释/判断优先用动效或图解，输入/操作优先用真实截图或录屏，成果图只在口播进入结果展示时出现。不得为了填画面，把结果卡提前复用到讲解段。
2. 截图负责证明，动效负责解释。两者同屏时必须先分配不重叠区域；标题承担定位作用时，即使画面已有截图也要保留独立标题区，不把标题压在需要阅读或验证的截图内容上。
3. 从布局开始就预留最终字幕带，而不是字幕生成后再挤画面。字幕启用后重新检查标题、截图、动效和字幕四层关系；关键信息不能靠遮挡人物脸部之外的随意覆盖来腾位置。
4. 每个截图/动效段至少检查：首帧、进入后 8–12 帧、落稳帧、中段、结束前帧，以及前后边界。空白首帧、标题迟到、截图截断、图文相压或边界闪帧均按阻断处理。
5. 返工按“口播语义与证据 → 版面层级与画面平衡 → 字幕安全 → 动效节奏 → 音乐音效”顺序修。上游未通过时不继续打磨下游，避免反复重做声音和动效。

### Phase 6: 完成候选
执行模式生成可审核候选；说明书模式明确尚未生成成片。制作预览卡确认后不再增加成片微确认，完成自检即导出审核候选并进入独立审核。

### Phase 7: 导出
1. 仅在导出能力实际可用时执行导出
2. 按 `brief.md` 平台计划分别导出对应规格（比例、时长、字幕嵌入方式），下载到 `<current_video>/06video/`
2.5 导出后先跑自动化技术检查，不只靠肉眼扫一遍：`ffprobe` 核对实际时长与脚本目标时长的差值；按最终剪辑点检查前后解码帧，`ffmpeg` 场景切换检测只能补充候选，不能保证发现所有叠化、短插帧或字幕残留；`ffmpeg`/`loudnorm` 核对全片响度是否落在目标区间。按实际问题选用 `video-editing-skill` 的 `references/upstream-qa.md` 中已安装的只读 QA：掉音、字幕活动、缺字、短闪帧或音视频解码覆盖，不默认全套运行。字幕活动检查需要最终时间轴字幕与独立人声，混音不能替代；疑点必须回看或回听，检测零候选不等于观感通过。问题记入 `edit-log.md` 并回同一个 ChatCut 工程修正。
3. 使用 `shared/templates/edit-log.md.template` 写入 `06video/edit-log.md`，记录成片相对路径、SHA-256、导出时间、版本、与分镜偏差和审核入口。内容存在自然分段（如教程按步骤、测评按对比项）时，按最终时间轴填写「章节/分段」表：时间戳、分段标题、一句话简介，供发布时接入抖音/小红书的分段功能；没有自然分段时该表留空，不勉强拆分。
4. 另做平台 UI 叠加预览，检查最终标题、正文、字幕、角标和画面是否互相遮挡；该预览进入完整成片与发布卡，不放入正式成片
5. 成片和 edit-log 真实存在后，用 `set_project_state.py` 把阶段更新为“审核中”、状态设为“进行中”、阻塞原因设为“无”
6. 立即委派独立审核员。审核通过后由复盘员把完整第一版、统一音乐/音效/动效、UI 预览、平台包装和审核结论组成“完整成片与发布卡”

### 退回处理
收到审核阻断项且责任岗位为剪辑师时（成片节奏、字幕、声音或导出问题），按退回项写明的受影响文件只改阻断项相关部分，用 `set_project_state.py` 把阶段退回“剪辑中”；整改完成后交回阻断项写明的复核入口，不重剪整片。
