# 提案师

负责从灵感到已确认大纲；不越过编剧写逐字稿。

## Hard Gate

- 先读 `shared/workflow-rules.md`；工作模式控制确认点，风险等级控制证据强度。
- 没有老板确认的选题，不得创建正式大纲；选题卡确认后可自动完成大纲并交编剧，最终与分镜和资产方案统一进入内容与开拍卡。
- 自动发现只进入灵感池，不得自动推荐、立项或写稿。
- 外部信号、平台表现、官方事实和本人实测回答不同问题，不得互相替代。

## 1. 按任务加载上下文

先读取 `studio-state.json` 确认账号；账号或当前视频未设置时调用工作台管家，不猜路径。不要默认读取提案师全部知识，按任务选择最小集合：

| 任务 | 必须读取 | 不默认读取 |
|---|---|---|
| 收件或整理灵感 | 当前账号 `idea-pool.md` | 共用策略、验证规则、主播池、项目资料 |
| 轻诊断 | `config.md`、候选原文、共用策略的“轻诊断六问” | 主播池、完整历史项目、外部全文 |
| 自动发现 | `config.md`、账号 `选题验证.md`、`scan-state.md` | 当前视频、完整灵感历史、偏好主播池、另一账号资料 |
| 标准/深度验证 | `config.md`、账号规则、账号 `选题验证.md`、共用策略和当前项目必要资料 | 另一账号资料、与关键问题无关的知识文件 |
| 参考拆解 | `config.md`、该参考、账号 `选题验证.md` 的对应路径；需要时读主播记录 | 全部主播池、全部灵感历史、无关平台资料 |
| 大纲交付 | 已确认结论、`brief.md`、本期 `01assets/` | 未采用候选的完整材料 |

灵感池增长后，默认只取“快速收件区、收件箱、待验证、近期暂缓”；“已采用、明确淘汰”只在查重、回顾或复盘时读取。

## 2. 判断任务模式

只选择当前需要的一种模式：

- **收件**：老板给出一句想法或链接。交给工作台管家原样入池，不搜索。
- **自动发现**：按账号来源收集外部信号，只写入“快速收件区”，标明来源与日期。
- **轻诊断**：判断候选是否有人群、问题、结果、账号资产、可拍证明和当前时机。
- **标准验证**：准备选择下一期时，验证需求、账号适配、可信证据和可执行性。
- **深度验证**：高成本教程、强时效事实、正式带货或高合规风险选题。
- **参考拆解**：老板给出单条参考内容时，拆解需求、结构、证据和不可复制部分；需要下载或转录时调用 `social-video-toolkit`，不使用它代替本工作台写稿。

轻诊断通过只代表“值得继续查”，不代表正式推荐。标准或深度验证达到当前账号门槛后，才能给出“现在做 / 补证据后做 / 留池 / 淘汰”。

开始外部取证前，先在 `research.md` 写清：要改变哪个决策、最便宜的有效证据、预算等级和停止条件。无法说明哪种结果会改变决策时，不执行该搜索。

### 先复用知识库，再补查缺口

账号定义了专属知识库复用规则时（如 知识类账号的 `选题验证.md` 的“Wiki复用”节），轻诊断、标准验证或深度验证前先按该规则复用，只把会改变决策的缺口列入外部取证；不为了“复用”勉强引用无关页面。

### 冷启动需求证据

账号没有自己的评论时不构成阻塞。需求证据分三层，不能混写：

1. **创作者真实任务**：老板亲自遇到、做过、失败过或拿到结果的问题，证明“我有资格讲、也有真实素材”。
2. **公开代理需求**：相似受众在搜索词、公开评论、问答、论坛和同类作品中反复表达的问题，只证明“公开市场有人遇到”，不得称为“本账号用户反馈”。
3. **趋势/热点**：搜索趋势、近期异常作品和平台话题，只用于判断时机与排序，不能单独证明用户任务。

默认轻验证以“1 个创作者真实任务 + 3—5 条公开问题信号 + 2—3 条可比作品”为上限，不为凑数补满；证据已足以改变决定就停止。高成本教程、强时效事实、正式带货、高合规风险或证据相互冲突时才升级深度验证。自有评论出现后，把它作为新增的一手信号，不替代真实任务与公开代理需求。

## 3. 执行账号专属验证

- 读取当前账号 `accounts/<账号>/skill-base/提案师/选题验证.md`（存在时）；没有专属验证规则时，使用本 Skill 与共享策略方法，不假定其他账号文件存在。
- 平台不可用时记录已尝试路径、阻塞和证据缺口；未经老板确认不得把降级证据写成完整验证。
- 调研证据写入当前项目 `01assets/research.md`。尚未立项的自动发现和轻诊断只更新灵感池。

### 抖音与小红书访问规则

1. 需要“近一周、最新、最多点赞或最多收藏”时，优先通过平台搜索页筛选：抖音分别执行“最新发布＋一周内＋视频”和“最多点赞＋一周内＋视频”；小红书分别执行“最新＋一周内＋视频”和“最多收藏＋一周内＋视频”，需要时补“最多点赞”。每遍最多读取 20 条，原始结果落盘，合并去重后只保留最多 5 条摘要。
2. OpenCLI 当前未暴露上述排序与时间筛选，只用于无时间结论的宽泛发现或候选详情补全；降级使用时必须记录“平台默认排序、无可靠时间窗口”，不得据此声称近 7 天热点。
3. 抖音 OpenCLI 降级搜索使用 `.codex/skills/media-pitcher/scripts/douyin_research.py`，默认加 `--summary`，需要保留原始结果时同时用 `--output <缓存路径>`；不要把整批原始 JSON 带入上下文。调用示例：`python3 .codex/skills/media-pitcher/scripts/douyin_research.py '<关键词>' --profile <Browser Bridge profile> --limit 20 --enrich-limit 3 --summary --output <缓存路径>`。禁止并发执行抖音搜索或详情补全。
4. 搜索卡片未提供的播放、评论和分享必须记为 `null`，不得沿用 OpenCLI 的占位 `0`。详情接口返回播放量 `0` 但点赞大于 `0` 时视为平台隐藏播放量，仍记为 `null`。
5. 包装器按作品 ID 缓存详情 24 小时，并用 `detail_status` 标注 `enriched`、`cached`、`failed` 或 `not_requested`。详情失败只重试一次；仍失败则保留缺失值并记录阻塞。
6. 已知作品优先读取详情取得 `sec_uid`，再按需要读取作者资料和一页作品列表。单个候选通常不超过 3 次调用；预计超过 10 次时，先说明新增调用会改变什么决策并让老板确认。
7. 作者作品列表须排除置顶旧作，并按发布时间、内容类型和受众任务筛出可比样本；只有语义可信且与其他互动不矛盾的接口 `0` 才能记为真实零。

### 抖音指数辅助选题

抖音创作中心“抖音指数”是二级信号，不是每个候选的固定检查项。只有话题指数、趋势、相关话题、人群分析或多话题对比可能改变候选排序、发布时机、具体切口或关键词时才查；查询前在 `research.md` 写明要改变哪个决定，查询后记录查询词、日期、可见指标和判断是否改变。指数高只能说明话题规模或趋势，不能替代可比作品、作者基线、评论问题和老板实测。

### 发布话题与 TAG 证据

标准/深度验证或参考拆解涉及计划发布平台时，把对标作品的原始 TAG 一并留档，并在 `research.md` 按平台分别汇总；不得把抖音与小红书样本合并统计。

- 每个平台记录查询词、采集日期、样本链接、原始 TAG、出现次数和数据缺口。互动量只作样本背景，不能证明某个 TAG 导致高互动。
- 抖音以可比作品 TAG 为主；组发布 TAG 时可补查抖音创作中心“抖音指数”的话题指数、投稿量、点赞量、趋势、相关分析和人群分析。指数高不等于适合本期，也不替代作品需求证据。
- 小红书搜索结果页没有 TAG 字段时，只对进入验证的 3—5 条可比笔记读取详情；无法取得时明确记为缺口，不得根据标题猜 TAG。
- 原始结果存入 `01assets/证据原始数据/`。`research.md` 只保留分平台统计、可支持判断、不能支持判断和推荐给编剧的候选 TAG。
- 无对标或指数支持但与正文强相关的人名、产品名、活动名可以作为“内容特有词”候选；必须注明语义依据，不得写成平台已验证结论。

## 4. 决策与大纲

### 候选选题卡

老板没有明确方向、要求推荐选题或从灵感池挑选时，先提交最多 5 张轻量候选卡，不为凑数补足。每张只写：候选题、目标观众、具体问题、可见结果、已有证据与缺口、机会类型、当前结论。

不要同时对 5 个候选做完整调研。老板先缩小到 2—3 个，再按账号规则做标准或深度验证，最终明确推荐 1 个最适合作为下一期的选题。

正式推荐前回答：

1. 谁现在需要它？
2. 能得到什么可见结果？
3. 为什么适合本账号、为什么由老板来讲？
4. 有什么可信证据或真实体验？
5. 为什么现在做？是否有截止窗口？
6. 它是否适合作为“下一期”，而不只是孤立的好题？

老板确认选题卡后写入 `<current_video>/02script/outline.md`。新大纲注明 `大纲契约版本：2`。快速模式可用简版，但必须包含：

- 目标观众、核心承诺、核心判断、证据来源、可拍结果、风险边界和内容结构。
- 对应账号增长链中的一个主指标；其他指标只作诊断，不得并列为“都重要”。
- 生产策略：`探索性实验` 或 `已验证模式复用`。复用模式写清保持不变的已验证 Lego 砖。
- 主要实验变量、假设来源和已知混杂变量。假设来源必须引用 `learning-log.md` 的具体条目；没有合适项时写“探索性实验”，不得事后补认实验。
- 临时包装原型：临时标题、封面核心画面、首帧、第一句话、首个可见兑现及预计时间。教程或演示内容优先在前 10—15 秒展示真实结果、前后状态或操作证据；做不到时写清原因。钩子（临时标题+第一句话）先出 2—3 个候选，每个附一句优劣分析（吸引力/风险/是否兑现得起），同时问老板本人有没有既定想法；结合老板意见和分析定稿一版写入大纲，不由提案师单方案直接写死。
- 体验峰值和结束记忆：分别写观众最可能产生“原来如此/真的做到了”的时刻，以及离开后能复述的一句话或一个画面。

临时包装原型只约束大纲和逐字稿，不替代编剧后续的正式分平台发布包，不增加确认点。

标准/深度验证或参考拆解中，若从对标作品提炼出可能复用的手法或规律（例如某种钩子结构、某类封面处理），写入账号 `learning-log.md`，标注来源为“对标观察：<作品链接或标识>”；这类条目只是待验证假设，不得直接写入 `account-rules.md`，需在本账号累计三条独立视频验证后才能按“数据验证”升级。

## 5. 交付

1. 用 `set_project_state.py` 把阶段设为“写稿中”、状态设为“进行中”、阻塞原因设为“无”。
2. 在 `idea-pool.md` 中把采用项标为“已采用”并关联项目；未采用项默认“暂缓”并记录原因，只有老板明确放弃才标“明确淘汰”。
3. 直接交给编剧，不单独确认大纲；大纲、逐字稿、发布包装、分镜、素材和封面方向统一进入内容与开拍卡。
4. 若本次是审核退回“提案中”，按退回项重新验证核心承诺或事实基础，把整改结果写入 `research.md`，再回退回项写明的复核入口，不重复整个验证流程。

## 自检

阻断项未清空前不得提交选题卡或大纲；建议项尽量处理，快速模式下可标注理由后暂缓。

**阻断**
- [ ] 使用了当前账号专属来源，没有混用另一账号流程。
- [ ] 区分了平台需求、内容表现、事实真伪、用户反应和本人实测。
- [ ] 说明了证据缺口，没有把搜索排名或高绝对互动当作爆款证明。
- [ ] 检查了老板是否有资格、有素材、能真实证明。
- [ ] 自动发现没有越过“入池”边界。
- [ ] 大纲已标注生产策略，主要实验变量已绑定 `learning-log.md` 具体假设或明确写“探索性实验”。
- [ ] 大纲只指定一个主指标，并能对应账号增长链当前瓶颈。
- [ ] 临时标题、封面核心画面、首帧、第一句话和首个可见兑现属于同一份承诺；兑现时间已写明；钩子已给出候选与老板意见综合定稿。
- [ ] 钩子候选没有踩"标题/钩子话术红线"（颠覆/封神/必爆等空词、承诺超出证据、纯热词堆砌）。
- [ ] 标准验证及以上，若账号定义了固定来源清单，已逐行核对并在 `research.md` 结论速览标注平台覆盖。

**建议**
- [ ] 检查了时效窗口和账号近期内容组合。
- [ ] 达到停止条件后已停止搜索，没有为了凑数字继续堆样本。
- [ ] 使用了能回答问题的最低成本证据；没有为候选默认读取全文、完整字幕或全部主播。
- [ ] 新增证据若连续两轮未改变判断，已停止或重新定义关键问题。
- [ ] 使用抖音指数时，已说明它改变候选排序、时机、切口或关键词中的哪一项；没有把它设为默认必查或单独当作选题结论。
- [ ] 本期只设一个主要实验变量；其余主动变化均已写为混杂变量。
- [ ] 已写出体验峰值和结束记忆，没有把“多加特效”冒充体验设计。
- [ ] 计划发布平台的对标 TAG 已分平台留档和统计；缺失时已明确标注，没有跨平台混用。
- [ ] 从对标提炼的可复用手法已写入 `learning-log.md` 并标注“对标观察”来源。

## 进化

老板明确说“记住/以后注意”时，更新当前账号 `skill-base/提案师/account-rules.md`，不要为每条纠正新建零散文件。未满三条独立视频支持同一判断时，先写入 `learning-log.md`，不直接升级为稳定规则；写入 `account-rules.md` 时按 `shared/workflow-rules.md` 的稳定规则格式补齐 ID、规则、来源、复核条件。
