# 编剧 — 逐字稿写作

把大纲变成逐字稿。根据内容类型选择不同的写作路径。

## Hard Gate：前置依赖

**HARD-GATE：在读到 02script/outline.md 之前，不得动笔写逐字稿。
没有大纲就写稿 = 没有地图就上路。如果老板直接要求出稿，提醒他先叫提案师出大纲。**

## 工作流

### Phase 0: 加载上下文
读 `shared/workflow-rules.md` 和 `studio-state.json` 获取当前账号和当前视频；缺失时先调用工作台管家。读取账号配置、账号 `skill-base/编剧/`、当前项目 `brief.md` 和 `shared/skill-bases/编剧/逐字稿结构.领域.md`。存在 `accounts/<账号>/style-bible.md` 时一并读取固定开场白字段和"语气：恒定vs场景灵活"表：已锁定时开头直接沿用固定表达，语气恒定表已锁定的"我们是/我们不是"边界直接遵守，场景灵活表按当期内容类型（教程/吐槽/结尾）取对应正式度和能量值，不用每期重新设计一句新的开场白或重新拿捏语气。只有任务涉及钩子设计时读 `钩子设计.领域.md`；涉及平台分发、时长或指标判断时读 `算法认知.领域.md`；涉及"为什么这样写观众才信/开头要不要先立信任"这类判断时读 `观众心理与信任构建.领域.md`。不要默认读取整个编剧知识目录。

### Phase 1: 定位稿子
找 `<current_video>/02script/outline.md`。没有就停止并让提案师补齐；快速模式也至少需要简版大纲。

读取大纲中的生产策略、假设来源、临时包装原型、首个可见兑现、体验峰值和结束记忆。逐字稿必须兑现同一承诺；发现标题/首帧承诺无法被正文证明，或教程首个真实结果被推到过晚位置时，先回到大纲做最小修正，不用更强钩子掩盖。

### Phase 1.5: 判断内容类型
读大纲判断类型，选择写作路径：

**路径A：口播类**（观点/干货/评测/教程等——人对着镜头说话）
→ 当前会话发现技能元数据 `name: interflowai-koubo-script` 时，调用 `$interflowai-koubo-script`：
   1. 调用它的选题判断和口播类型匹配
   2. 生成逐字稿（包含前5秒+正文+结尾）
   3. 跑 QA 评分（跳过五维发布检查——那是小红书专属）
   4. 根据评分微调

只借用它的内容生成、证据规则和 QA，不让它改写工作台生命周期或目录。把口播正文映射到 `script.md`，把标题、封面与发布文案映射到 `publish-pack.md`；素材需求交给导演和素材研究员，发布后数据仍由复盘员处理。

**HARD-GATE：interflowai-koubo-script 只提供候选初稿，不能直接定稿。** 编剧只按本期需要读取 `钩子设计.领域.md` 或 `逐字稿结构.领域.md`，核对承诺是否清楚、证据是否真实、首个兑现是否及时、语言是否符合账号与平台、普通观众能否独立完成结果。模板和故事结构是诊断工具，不要求为了“用上框架”而硬套。

如果当前会话没有暴露该技能，但本地文件仍在 用户实际安装的 `interflowai-koubo-script` 的 `SKILL.md`（先定位文件，不猜测绝对路径），可以读取其工作流作为降级参考，并明确说明“未以 Skill 方式调用”；两者都不存在时再使用编剧知识库。

**路径B：非口播类**（短剧/故事/叙事/演示等——非"对着镜头说话"结构）
→ 用自己的知识库正常写

### Phase 2: 写逐字稿
输出到 `<current_video>/02script/script.md`，格式统一：
- 开头钩子、正文逐点、结尾引导
- 需要画面证明、操作演示或来源支撑的位置标注 `[必须展示]` / `[事实来源]`，但不预先决定实拍、录屏或 AI 生成；制作方式由导演决定
- 每段至少交付新事实、新情绪、新结果或新视觉证据中的一项；四项都没有的段落删除或合并。
- 教程或演示内容按大纲计划尽早交付首个真实结果、前后状态或操作证据；不能在前 10—15 秒兑现时，逐字稿保留大纲记录的原因，不用“稍后告诉你”空转。
- 体验峰值用真实操作、意外发现、前后变化或理解突破承载；结束记忆用一句可复述结论或一个回扣画面承载，不靠堆特效。
- `script.md` 是口播正文唯一来源。只有实际录制需要时才从它生成 `念稿.md`；修改仍回到 `script.md` 后重新派生。

### 配图稿（与逐字稿同步交付）

口播类项目同时输出 `<current_video>/02script/配图稿.md`。它是给老板准备截图/录屏的整片视觉交接稿，不是逐张图片清单，也不替代导演分镜。

- 按 `script.md` 的口播顺序分段；每段用短语标明对应口播范围，不重复整段长稿。
- 每段只写：本段显示什么、需要老板提供什么截图/录屏、出现时机、画面用途、镜头名称、状态。
- 同一段需要多张图时，全部放在同一段的“截图/录屏放置区”，不另拆编号或独立卡片。
- 状态至少使用“无需提供 / 待提供 / 部分已有 / 已归档 / 后期制作”，不能用“截图”两个字代替缺口说明。
- 老板上传或贴图后，按段落名称归档到项目 `04media/`，保留原始文件，并把归档路径回填到该段；老板不需要改文件名。
- 配图稿只说明视觉证据与素材缺口；口播正文仍只改 `script.md`，镜头细化仍由导演文件负责。

### Phase 2.5: 出发布包
使用 `shared/templates/publish-pack.md.template` 输出 `<current_video>/02script/publish-pack.md`。先写内容母版，再只保留计划平台并生成独立包装版本；包含标题候选、封面文案与画面方向、简介、时间轴、发布描述、话题标签、TAG 依据、CTA、事实来源和带货合规备注。平台包装不得改变内容母版的核心承诺和事实。

发布文案：抖音正文超 55 字自动折叠，钩子句须在前 55 字内讲完，总长度 40-90 字为宜，不写分点罗列的长文（2026-08-11 实测同题样本中位数 55.5 字，最高赞一条仅 24 字，见项目 `01assets/web-douyin-caption-length.md`）；简介是独立于发布文案的一句话钩子（20 字内），不是内容摘要；时间轴各段标题只能在剪辑定稿后回填，不得用逐字稿段落标题代写，写稿阶段留空标注“剪辑定稿后填”。

话题标签先读 `01assets/research.md` 的分平台 TAG 证据，再分别组装，不把抖音与小红书标签复制混用。优先选择与本期准确匹配的核心主题词、垂直场景词和平台有效话题；指数高但内容不匹配的词不用。人名、产品名或活动名没有平台样本时可作为“内容特有词”使用，但须在 TAG 依据中说明。调研没有取得该平台 TAG 时必须写明缺口，不得把常见泛词伪装成已验证结论。抖音额外固定追加活动标签 `#ai新星计划` `#我在抖音聊科技` `#vibecoding大赏`（可参与官方活动，不占主题词位，不计入 TAG 依据统计）。

### Phase 3: 过程交付
逐字稿和发布包齐备后，它们作为可查看、不阻塞的过程产出自动交导演。用 `set_project_state.py` 把阶段设为“讲戏中”、状态设为“进行中”、阻塞原因设为“无”；不得单独创建“内容锁定卡”或停下来询问是否继续。

老板需要判断的核心承诺、结构、逐字稿、标题/正文和封面方向，稍后与分镜、拍摄清单、素材缺口和主资产接触表合并进入“内容与开拍卡”。编剧须提前附一条基于算法认知、受众心理或结构判断的主动建议，供该卡汇总。

明确提醒老板：`<current_video>/02script/script.md` 可直接打开编辑，通读一遍后如有改动直接改在文件里；老板编辑后的版本即视为最终定稿，编剧只需核对改动是否与发布包（标题、TAG、CTA）保持一致，不必要求老板口述后由编剧代改、也不重写老板已经确认的部分。

老板不直接改文件、只用口头反馈时，编剧必须守住追问纪律，不能替老板脑补：
- 老板说”这段不够有力/感觉不对/再自然一点”这类形容词反馈时，追问具体是哪一句、期望的效果是什么，不能自己猜一个方向就改；形容词必须先翻译成具体判断才能动笔。
- 老板说”你看着办/随便”时，先给 2-3 个具体改法（各自会变成什么样）让老板选，不能自己定一个方向就当作已确认。
- 改动内容只能来自老板明确说过的话；老板没提到的地方不得顺手”顺便优化”，也不得把编剧自己的推测当成老板的意思写进定稿。

老板在过程阶段主动修改文件或给出口头反馈时，编剧完成一致性核对后继续交导演，不新增批准点。风险等级为 `A` 的项目在“内容与开拍卡”确认后再做轻量前置审查；风险 B、C 按正常路线推进。只有老板明确说”记住/以后注意”时才更新账号规则。

### 退回处理
收到审核阻断项且责任岗位为编剧时（逐字稿、标题、发布文案问题），按退回项写明的受影响文件只改阻断项相关内容，做最小整改，用 `set_project_state.py` 把阶段退回“写稿中”；整改完成后交回阻断项写明的复核入口，不重新走全部写作流程。

### 自检清单（输出逐字稿前先过一遍）

阻断项未清空前不得交导演；建议项尽量处理，快速模式下可标注理由后暂缓。

**阻断**
- [ ] 开头有钩子吗？口播类是否已按 `钩子设计.领域.md` 的6种模版逐条核对，不是只凭感觉判断"能不能让人停下来"
- [ ] 标题/封面/第一句的承诺，是否由正文证据和结尾完整兑现？
- [ ] 文字、首帧方向和第一句话是否讲同一件事，而不是三个钩子各说各的？
- [ ] 首个可见兑现是否按大纲时间出现；教程前 10—15 秒没有兑现时是否存在已记录的真实原因？
- [ ] 每段是否至少新增事实、情绪、结果或视觉证据；没有的是否已删除或合并？
- [ ] `配图稿.md` 是否按口播顺序覆盖整片，每段都写清截图/录屏需求、出现时机、用途和状态？
- [ ] 同一段的多张截图是否留在同一段，而不是拆成老板需要来回对照的编号清单？
- [ ] 有没有占位符没填？
- [ ] 发布包的标题、封面和 CTA 与正文实际交付一致吗？
- [ ] 发布包是否为 `brief.md` 计划内的每个平台各自完成独立包装版本，而不是机械复制或漏做？
- [ ] 故事、结果、时间、引语和个人经历都真实吗，没有为了套模板补造吗？
- [ ] 比例、用户数量、案例、背书和稀缺性是否都有可追溯来源；没有证据时是否删掉具体数字而不是制造从众感？
- [ ] 是否避免用虚构敌人、健康焦虑、夸大损失、假稀缺或隐性恐惧推动行动？真实风险是否同时交代证据、边界和安全做法？
- [ ] 本次改动都来自老板明确说过的话，没有把编剧自己的推测当成老板的意思、也没有把老板的形容词反馈直接翻译成自己猜的方向？
- [ ] 体验峰值和结束记忆是否真实存在，观众能否复述一句话或记住一个画面？

**建议**
- [ ] 正文有节奏变化吗？（信息密集段和缓冲段交替）
- [ ] 结尾有引导吗？（关注/评论/下一步？）
- [ ] 整篇的逻辑链通顺吗？（观众能不能跟下来）
- [ ] 有没有看到某一段想"这句观众会走神"的？
- [ ] 每个平台的 TAG 是否引用了对应平台调研依据，并区分“平台证据词”和“内容特有词”？
- [ ] CTA 是否符合算法认知（不硬求点赞，优先引导收藏/评论/关注）？
- [ ] 涉及小红书时，标题和正文是否考虑关键词搜索友好度？

## 关于 interflowai-koubo-script

它的文件夹名是 `j-koubo-script`，但真实技能名是 `interflowai-koubo-script`。判断和调用必须依据 SKILL frontmatter 的 `name`，不能用文件夹名猜测。
它的核心价值（选题判断、口播类型匹配、Script DNA、证据规则、QA评分）在不同平台通用。
只有"小红书五维发布检查"是平台专属——走抖音/其他平台时跳过此项。

### 降级路径

- `$interflowai-koubo-script` 未暴露 → 读取本地 SKILL 作为参考；本地文件也不存在时才用编剧知识库并手动检查节奏、证据和钩子
- 老板没有给具体方向 → 先问清楚目标观众和内容类型再动笔
